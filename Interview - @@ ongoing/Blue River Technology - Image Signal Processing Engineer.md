### **二、核心技術深度解析 (針對See & Spray場景)**

---

#### **1. 去馬賽克 (Demosaicking)**

- **對人類視覺的影響 (for Human Vision):** 在See & Spray系統中，人類視覺主要用於**系統校準、故障排除和效果抽查**。現場的工程師或技術人員需要透過螢幕觀看攝影機的即時畫面。如果去馬賽克品質差，導致畫面充滿色彩偽影或模糊，他們將無法準確判斷系統是否正常工作（例如，無法看清鏡頭是否髒污，或無法確認AI標記的雜草是否正確）。
    
- **對機器視覺的影響 (for Machine Vision):** 這是**最關鍵**的。AI模型辨識作物和雜草，依賴的是極其細微的**形狀、紋理和顏色**差異。
    
    - **紋理破壞:** 差的去馬賽克會在植物葉片的邊緣和葉脈上產生偽色或拉鍊效應，這些錯誤的「紋理」會嚴重干擾CNN對葉片真實特徵的提取。
    - **形狀誤判:** 演算法產生的模糊會使細小的雜草幼苗邊緣不清晰，降低其被偵測到的機率。
    - **對See & Spray系統而言，一個理想的去馬賽克演算法，其首要目標不是「好看」，而是最大程度地「保真」，為後續的CNN提供最乾淨、最準確的原始圖像資訊。**
        
- **主流技術:** 高品質插值演算法如 **AHD** 依然是業界的基石，因為它們穩定、可預測且計算開銷相對固定。在一個追求極致穩定的工業級應用中，這些成熟的技術通常是首選。
    
- **最新技術與趨勢:** 結合JD中的第三點，這裡的趨勢是**探索直接在Bayer RAW數據上進行AI辨識**。這可以完全繞過去馬賽克這一步，避免了資訊損失和引入偽影的風險。另一個方向是，訓練一個**特定任務導向的去馬賽克神經網路**，其優化目標不是傳統的PSNR或SSIM指標，而是**後端雜草辨識CNN的準確率**。也就是說，只要能讓後面的CNN認得更準，即便去馬賽克後的影像人眼看起來有些奇怪也沒關係。

#### **2. 色彩校正 (Color Correction)**

- **對人類視覺的影響:** 和去馬賽克類似，準確的色彩能幫助現場人員判斷植物的健康狀況。例如，作物葉片發黃可能表示缺乏營養，準確的色彩還原對人工診斷很重要。
    
- **對機器視覺的影響:** **極度重要，甚至是系統成敗的關鍵之一**。
    
    - **色彩恆常性 (Color Constancy):** 這是終極目標。同一種雜草，無論是在陽光直射下（色溫偏藍），還是在傍晚時分（色溫偏紅），或是在多雲天氣（光線散射），它的顏色在經過您的ISP處理後，都應該呈現出高度一致的數值。
    - **可區分性:** 作物（如玉米）和雜草（如莧菜）在幼苗期可能顏色非常相近。CNN正是依賴ISP提供的穩定、精確的色彩資訊（例如，那細微的綠色色調差異）來區分它們。如果白平衡不準，或色彩校正矩陣（CCM）不穩定，導致兩種植物的顏色在數據上發生重疊，CNN將徹底失效。
    - **魯棒性:** 您的色彩校正流程必須對一天中光照的劇烈變化、以及不同地理位置的陽光光譜差異都具有極高的魯棒性。
        
- **主流技術:** 基於統計的AWB演算法（灰度世界、白點檢測）和在實驗室中用標準色卡標定出的**固定CCM**。這是實現基礎色彩校正的標準做法。
    
- **最新技術與趨勢:** **AI驅動的色彩校正**是這個領域的未來。
    
    - **場景感知的白平衡 (Scene-Aware AWB):** 訓練一個神經網路來辨識當前的場景元素（土壤、綠色植物、天空），並基於這些高階資訊來推斷環境光源，從而進行極其精準的白平衡。例如，模型知道「土壤」在不同光線下可能的顏色範圍，可以用它作為錨點來校正色彩。
    - **動態CCM:** 建立一個能根據光源色溫、亮度等因素動態調整CCM參數的AI模型，確保在任何光照下都能達到色彩恆常性。

#### **3. 色調映射 (Tonemapping)**

- **對人類視覺的影響:** 農業場景的動態範圍極大：陽光直射下的亮黃色土壤和作物投下的深邃陰影並存。一個好的色調映射能讓操作員在螢幕上同時看清亮處和暗處的細節，確保沒有任何視覺盲區。
    
- **對機器視覺的影響:** **核心是資訊保全**。
    
    - **避免資訊損失:** 這是最重要的。如果一個雜草剛好長在噴灑車或高大作物的陰影裡，一個糟糕的色調映射演算法可能會把陰影部分處理成「死黑」，所有細節丟失。這會導致CNN完全**看不見**這個雜草，使得偵測率大幅下降，違背了系統「一致性」的要求。同理，亮部細節的過曝也會導致資訊損失。
    - **保持一致性:** 不同的色調映射曲線會改變圖像的局部對比度。您需要確保無論物體在亮處還是暗處，其呈現給CNN的特徵（如梯度、紋理）都是相對一致的。
        
- **主流技術:** 局部色調映射 (Local TMOs) 是首選，因為它們能更好地保留局部對比度，提升陰影和高光區域的細節。但它們的計算量通常較大，需要為邊緣計算進行深度優化。
    
- **最新技術與趨勢:**
    
    - **RAW數據直接處理:** 對於機器視覺任務，最理想的情況可能是**完全繞過色調映射**。直接將感測器輸出的高位元深度（如12-bit或14-bit）的線性RAW數據提供給CNN。這樣做可以從根本上避免因色調映射壓縮動態範圍而導致的任何資訊損失。
    - **雙路輸出ISP (Dual-path ISP):** 這是一個非常先進和實用的架構。ISP pipeline分叉成兩路：
        
        1. **機器視覺路徑:** 進行最少但必要的處理（如黑電平、鏡頭陰影校正），然後將高動態範圍的線性數據直接送給CNN。
        2. **人類視覺路徑:** 在第一路的基礎上，繼續進行完整的色彩校正、色調映射、銳化等處理，生成一張視覺效果良好、便於人類觀察的SDR影像，用於監控和除錯。 這種架構完美地解決了人類視覺和機器視覺對影像品質需求不同的矛盾。

總之，這是一個要求極高、挑戰與機遇並存的職位。您不僅需要是傳統ISP的專家，還必須是一位能夠站在AI模型角度思考問題，並能將兩者無縫結合的跨領域人才。

### **1. 去馬賽克 (Demosaicking)**

#### **非AI-based方法 (傳統方法)**

- **原理:** 基於一個核心假設：相鄰像素之間的顏色是高度相關且平滑過渡的。演算法會分析一個像素周圍的Bayer pattern，並透過插值 (Interpolation) 來估算缺失的顏色。高品質的演算法會進一步分析邊緣方向、紋理複雜度等資訊，來避免在邊緣上進行錯誤的插值，從而減少偽影。
- **舉例:**
    - **雙線性插值 (Bilinear):** 簡單地對周圍同色像素進行平均，速度快但效果差。
    - **AHD (Adaptive Homogeneity-Directed):** 經典的高品質演算法，它會判斷像素周圍是平坦區域還是邊緣，並智慧地選擇插值方向，效果很好。
    - **LMMSE (Linear Minimum Mean Square Error):** 基於局部色彩相關性的統計模型，試圖最小化估算誤差。
- **優點:**
    1. **可預測性高:** 演算法的行為完全由其數學定義決定，容易除錯。
    2. **無需訓練數據:** 不依賴外部數據集，部署簡單。
    3. **計算穩定:** 運算複雜度固定，易於在硬體上實現和優化。
- **缺點:**
    1. **性能瓶頸:** 依賴的假設在複雜場景（如高頻紋理、細密線條）中會失效，導致難以根除的偽影（如摩爾紋、拉鍊效應）。
    2. **設計複雜:** 開發更高級的演算法需要深厚的數學和訊號處理知識，且參數調校困難。

#### **AI-based方法 (深度學習方法)**

- **原理:** 將去馬賽克視為一個「影像重建」問題。使用一個深度卷積神經網路（如U-Net架構），輸入是Bayer RAW數據，輸出的目標是與之對應的真實、無瑕疵的全彩RGB影像。在訓練過程中，模型會學習到自然影像中顏色、紋理、結構的內在統計規律，這種學習到的先驗知識遠比傳統方法的簡單假設要強大得多。
- **舉例:**
    - **端到端CNN模型:** 直接訓練一個大型CNN，從RAW檔一步到位輸出高品質RGB影像，這個過程可以同時完成去馬賽克、降噪等多個任務（**聯合優化**）。
- **優點:**
    1. **品質卓越:** 在客觀指標（PSNR/SSIM）和主觀視覺上，目前最頂尖的AI方法顯著優於所有傳統方法，能產生更清晰、更少偽影的影像。
    2. **聯合優化:** 能夠在一個模型中同時處理多個ISP任務，避免傳統pipeline中各步驟誤差累積的問題，達到全局最優。
    3. **適應性強:** 對於傳統方法難以處理的複雜紋理和場景，AI模型由於見過大量類似數據，表現通常更好。
- **缺點:**
    1. **數據依賴:** 需要龐大且高質量的成對數據集（RAW + Ground Truth RGB），獲取成本高昂。
    2. **計算昂貴:** 訓練過程需要大量GPU資源。推論（Inference）時雖然可以被優化，但通常比傳統方法更耗資源。
    3. **可解釋性差:** 「黑盒子」特性。當模型在某個特定場景下失敗時，很難從理論上分析其根本原因。
    4. **泛化問題:** 如果訓練數據的多樣性不足，模型在遇到從未見過的場景類型時，可能會產生奇怪且不可預測的結果。

### **2. 色彩校正 (Color Correction) - 以自動白平衡(AWB)為例**

#### **非AI-based方法 (傳統方法)**

- **原理:** 基於對場景的統計假設。演算法不「理解」影像內容，只對像素值進行統計分析來猜測光源顏色。
- **舉例:**
    - **灰度世界 (Gray World):** 假設整個場景所有物體顏色的平均值是中性灰色。如果平均色偏黃，就認定光源是黃色，並進行補償。
    - **白點檢測 (White Patch):** 假設場景中最亮的像素點是純白色反射物體。如果最亮的點偏藍，就認定光源是藍色。
    - **色域邊界法:** 結合以上兩種，在色彩空間中尋找可能的有效光源顏色。
- **優點:**
    1. **簡單快速:** 計算量極小，非常容易實現。
    2. **無需數據:** 不依賴任何訓練。
    3. **行為穩定:** 在滿足其假設的場景下（如色彩豐富的戶外風景），效果不錯。
- **缺點:**
    1. **假設脆弱:** 當場景不滿足假設時（如拍攝大面積的單色物體，像紅色牆壁），會徹底失敗。
    2. **不夠智慧:** 無法處理複雜情況，如混合光源、或帶有強烈色彩傾向的藝術場景。

#### **AI-based方法 (深度學習方法)**

- **原理:** 將AWB視為一個「光源估計」問題，並從影像的「語義內容」中尋找線索。CNN模型被訓練來識別影像中的物體（如天空、皮膚、綠植）和材質，並利用這些物體的「記憶色」（Canonical Colors）作為參考，來推斷環境光是什麼顏色。
    
- **舉例:**
    - **分類/回歸模型:** 訓練一個CNN來直接回歸光源的色溫值，或者將其分類到幾種預設的光源類型中。
    - **場景理解模型:** 結合語義分割，先將影像中的皮膚、天空等區域分割出來，然後基於這些區域的顏色來進行更精準的白平衡。
- **優點:**
    1. **準確性高:** 由於模型「理解」內容，其準確性遠超傳統統計方法，特別是在困難場景下。
    2. **魯棒性強:** 對於大面積單色、複雜光源等傳統方法失效的場景，AI方法依然能做出合理的判斷。
    3. **可學習性:** 可以針對特定應用場景（如人像、醫療）進行特化訓練，達到更好的效果。
- **缺點:**
    1. **數據需求:** 需要大量在不同光源下拍攝的、帶有光源資訊標註的影像數據。
    2. **計算開銷:** 推論需要神經網路運算，比簡單的統計法複雜得多。
    3. **潛在偏見:** 如果訓練數據有偏見（例如，大部分是白天戶外場景），模型在室內低光下的表現可能會下降。

### **3. 色調映射 (Tonemapping)**

#### **非AI-based方法 (傳統方法)**

- **原理:** 使用一個手動設計的、非線性的數學函數（色調曲線），將輸入的高動態範圍（HDR）像素值映射到輸出的低動態範圍（SDR）。這個函數的目標是在壓縮動態範圍的同時，儘可能保留視覺對比度和細節。
- **舉例:**
    - **全局TMOs (Global):** 如 **Reinhard TMO**，對整個影像應用同一條曲線，簡單快速。
    - **局部TMOs (Local):** 如 **iCAM06**，根據每個像素及其周邊區域的亮度來動態調整映射，能更好地保留局部細節，但計算複雜。
- **優點:**
    1. **控制性強:** 所有的參數（對比度、亮度等）都有明確的物理或數學意義，方便手動調校。
    2. **實時性好:** 許多全局和優化過的局部演算法都能夠達到即時處理速度。
- **缺點:**
    1. **效果上限:** 難以生成兼具高保真度和藝術美感的影像，容易產生光暈 (Halos) 或對比度失真等問題。
    2. **參數複雜:** 高品質的局部TMOs通常有大量參數，需要專家進行繁瑣的調整才能達到最佳效果。
#### **AI-based方法 (深度學習方法)**

- **原理:** 不再追求數學上的最優壓縮，而是學習人類對影像的「美學偏好」。模型（特別是生成對抗網路GAN）被訓練來模仿專業攝影師的後期處理風格。
- **舉例:**
    - **監督學習:** 收集大量由專業人士處理過的HDR-SDR影像對，訓練一個CNN來學習這種映射風格。
    - **生成對抗網路 (GANs):** 讓一個「生成器」網路負責進行色調映射，另一個「判別器」網路負責判斷其輸出的影像是像機器生成的還是像專業攝影作品。兩者相互博弈，最終生成器能產出非常自然、悅目的影像。
- **優點:**
    1. **主觀品質高:** 產出的影像通常更符合人類的審美，色彩、對比度和氛圍感都非常出色。
    2. **風格化:** 可以學習特定的風格，例如電影感、日系小清新等。
    3. **細節保留:** 能夠在壓縮動態範圍的同時，智慧地保留或甚至增強重要的紋理細節。
- **缺點:**
    1. **真實性問題:** 有時為了追求「好看」，可能會「創造」出原始HDR影像中不存在的細節或顏色，對於需要高保真度的科學或工業應用可能是個問題。
    2. **穩定性與一致性:** GAN等模型的訓練可能不穩定，且對於相似的輸入，輸出可能會有些微的隨機變化，這在需要高度一致性的應用中是個挑戰。
    3. **資源消耗大:** GANs的訓練和推論通常是三者中最耗費計算資源的。





#### opencv functions

OpenCV 是一個強大的電腦視覺工具庫，它為影像訊號處理（ISP）的各個環節提供了許多基礎且高效的工具。 值得注意的是，OpenCV 的設計哲學是提供**演算法的 building blocks (建構模塊)**，而不是像手機相機那樣提供一鍵式的全自動解決方案。因此，您通常需要組合使用這些功能來建構一個完整的處理流程。以下將分別針對 Demosaicking、Color Correction 和 Tonemapping，詳細解釋 OpenCV 支援的方法，並提供簡單的 Python 範例程式碼。

### **一、去馬賽克 (Demosaicking)**

OpenCV 將去馬賽克功能整合在一個非常核心的函數 `cv2.cvtColor()` 中。它透過特定的色彩空間轉換代碼，可以將單通道的 Bayer RAW 格式影像轉換為三通道的彩色影像。OpenCV 內部實作的是一種高效且品質良好的插值演算法，類似於基於梯度的邊緣感知方法，效果遠優於基礎的雙線性插值。

#### **OpenCV 支援的方法**

您需要根據您的感測器 Bayer pattern 的排列方式（即左上角 2x2 像素的顏色順序），選擇對應的轉換代碼。常見的代碼有：
- `cv2.COLOR_BayerBG2BGR`: Bayer pattern 為 BGGR...，轉換為 BGR 影像。
- `cv2.COLOR_BayerGB2BGR`: Bayer pattern 為 GBRG...，轉換為 BGR 影像。
- `cv2.COLOR_BayerRG2BGR`: Bayer pattern 為 RGGB...，轉換為 BGR 影像。
- `cv2.COLOR_BayerGR2BGR`: Bayer pattern 為 GRBG...，轉換為 BGR 影像。

還有對應的 `...2RGB` 版本，可以根據您的需求選擇。
#### **範例程式碼 (Example Code)**

```Python
import cv2
import numpy as np

# 1. 建立一個模擬的 Bayer pattern 影像 (單通道)
# 假設 pattern 是 RGGB (即 cv2.COLOR_BayerRG2BGR)
# R G
# G B
height, width = 480, 640
# 先建立一個全零的灰度影像
bayer_image = np.zeros((height, width), dtype=np.uint8)

# 填充 R, G, B 的值來模擬感測器輸出
bayer_image[0::2, 0::2] = 200  # R 通道位置，給定一個較高的值
bayer_image[0::2, 1::2] = 100  # G (在R的同行)
bayer_image[1::2, 0::2] = 100  # G (在R的同列)
bayer_image[1::2, 1::2] = 150  # B 通道位置

print(f"原始 Bayer 影像的維度: {bayer_image.shape}")
print(f"原始 Bayer 影像的資料類型: {bayer_image.dtype}")

# 2. 使用 cv2.cvtColor() 進行去馬賽克
# 我們使用 cv2.COLOR_BayerRG2BGR 因為我們模擬的是 RGGB pattern
debayered_image_bgr = cv2.cvtColor(bayer_image, cv2.COLOR_BayerRG2BGR)

print(f"去馬賽克後的 BGR 影像維度: {debayered_image_bgr.shape}")
print(f"去馬賽克後的 BGR 影像資料類型: {debayered_image_bgr.dtype}")

# 顯示結果 (在實際應用中)
# cv2.imshow("Bayer RAW (Grayscale)", bayer_image)
# cv2.imshow("Demosaicked Image (BGR)", debayered_image_bgr)
# cv2.waitKey(0)
# cv2.destroyAllWindows()

# 為了在 Colab/Jupyter 中顯示，我們可以使用 matplotlib
import matplotlib.pyplot as plt

plt.figure(figsize=(12, 6))
plt.subplot(1, 2, 1)
plt.imshow(bayer_image, cmap='gray')
plt.title("模擬的 Bayer RAW 影像 (單通道)")
plt.subplot(1, 2, 2)
# Matplotlib 顯示順序是 RGB，所以我們需要將 BGR 轉為 RGB
debayered_image_rgb = cv2.cvtColor(debayered_image_bgr, cv2.COLOR_BGR2RGB)
plt.imshow(debayered_image_rgb)
plt.title("去馬賽克後的彩色影像")
plt.show()
```

### **二、色彩校正 (Color Correction)**

OpenCV 沒有提供一個名為 `auto_color_correct()` 的全自動函數，但它提供了實現各種色彩校正演算法所需的核心工具。最常見的兩種校正方式是**白平衡**和**色彩矩陣校正**。

#### **OpenCV 支援的方法**

1. **白平衡 (White Balance):** OpenCV 沒有內建的「灰度世界」或「完美反射」等一鍵式白平衡算法，但它們可以輕易地用 OpenCV 的基本矩陣運算和統計函數（如 `cv2.mean()`, `cv2.split()`, `cv2.merge()`）來實現。
    
2. **色彩矩陣校正 (Color Correction Matrix):** 如果您有一個 3x3 的色彩校正矩陣（CCM），您可以使用 `cv2.transform()` 函數將其應用於影像的每個像素，從而將影像從感測器的色彩空間轉換到標準色彩空間（如 sRGB）。
    

#### **範例程式碼 (以 "灰度世界" 演算法實現白平衡)**

"灰度世界" (Gray World) 演算法假設影像中的所有顏色的平均值應該是中性灰色。我們可以基於這個假設來校正色偏。

Python

```
import cv2
import numpy as np
import matplotlib.pyplot as plt

# 1. 建立一個模擬有色偏的影像
# 這裡我們手動創建一個偏黃色的影像
image_bgr = np.zeros((300, 400, 3), dtype=np.uint8)
# 填充一些顏色，讓 B 通道較弱，R 通道較強，模擬黃昏光線
image_bgr[:, :, 0] = 100  # Blue
image_bgr[:, :, 1] = 200  # Green
image_bgr[:, :, 2] = 220  # Red

# 2. 實現灰度世界演算法
# 分離 B, G, R 通道
b, g, r = cv2.split(image_bgr)

# 計算每個通道的平均值
avg_b = np.mean(b)
avg_g = np.mean(g)
avg_r = np.mean(r)

# 計算整個影像的平均灰度值
avg_gray = (avg_b + avg_g + avg_r) / 3

# 計算每個通道需要縮放的比例
scale_b = avg_gray / avg_b
scale_g = avg_gray / avg_g
scale_r = avg_gray / avg_r

# 應用縮放比例到各個通道
b_corrected = np.clip(b * scale_b, 0, 255).astype(np.uint8)
g_corrected = np.clip(g * scale_g, 0, 255).astype(np.uint8)
r_corrected = np.clip(r * scale_r, 0, 255).astype(np.uint8)

# 合併校正後的通道
corrected_image_bgr = cv2.merge([b_corrected, g_corrected, r_corrected])


# 3. 顯示結果
image_rgb = cv2.cvtColor(image_bgr, cv2.COLOR_BGR2RGB)
corrected_image_rgb = cv2.cvtColor(corrected_image_bgr, cv2.COLOR_BGR2RGB)

plt.figure(figsize=(12, 6))
plt.subplot(1, 2, 1)
plt.imshow(image_rgb)
plt.title(f"原始影像 (偏黃)\nAvg R={avg_r:.1f}, G={avg_g:.1f}, B={avg_b:.1f}")

plt.subplot(1, 2, 2)
plt.imshow(corrected_image_rgb)
avg_b_new, avg_g_new, avg_r_new = np.mean(b_corrected), np.mean(g_corrected), np.mean(r_corrected)
plt.title(f"灰度世界校正後\nAvg R={avg_r_new:.1f}, G={avg_g_new:.1f}, B={avg_b_new:.1f}")
plt.show()

```

### **三、色調映射 (Tonemapping)**

對於色調映射，OpenCV 在 `photo` 模組中提供了一系列功能完善的類別，專門用於處理高動態範圍（HDR）影像。

#### **OpenCV 支援的方法**

這些演算法的目標是將浮點數格式的 HDR 影像（數值範圍可以遠大於 [0, 1]）壓縮到適合顯示的 [0, 1] 範圍，同時保留亮部和暗部的細節。您需要先創建一個色調映射物件，然後使用它的 `process` 方法。

- `cv2.createTonemapDrago()`: 基於人眼對亮度變化的對數響應，能很好地處理非常高動態範圍的影像。
    
- `cv2.createTonemapReinhard()`: 基於傳統攝影中的 "Dodging & Burning" 技術，模擬攝影師調整局部亮度的過程，效果自然。
    
- `cv2.createTonemapMantiuk()`: 旨在最大化保留影像的對比度，產生的影像看起來可能更「鮮活」。
    
- `cv2.createTonemap()`: 一個基礎的伽瑪校正色調映射器。
    

#### **範例程式碼 (使用 Reinhard TMO)**

Python

```
import cv2
import numpy as np
import matplotlib.pyplot as plt

# 1. 建立一個模擬的 HDR 影像 (32位元浮點數)
# HDR 影像的數值範圍遠超 [0, 255] 或 [0, 1]
# 我們建立一個從暗到亮的漸變，並將其乘以一個大數來模擬高動態範圍
height, width = 300, 500
hdr_image = np.zeros((height, width, 3), dtype=np.float32)
# 創建一個從左到右的漸變
gradient = np.linspace(0.01, 50, width, dtype=np.float32)
for i in range(height):
    hdr_image[i, :, 0] = gradient * 0.8 # B
    hdr_image[i, :, 1] = gradient * 1.0 # G
    hdr_image[i, :, 2] = gradient * 1.2 # R

print(f"模擬 HDR 影像的數值範圍: min={hdr_image.min():.2f}, max={hdr_image.max():.2f}")
print(f"模擬 HDR 影像的資料類型: {hdr_image.dtype}")


# 2. 使用 Reinhard 色調映射演算法
# 創建 Reinhard Tonemap 物件
# gamma: 伽瑪值，值越小影像越亮。預設 1.0
# intensity: 亮度調節，正值更亮，負值更暗。預設 0.0
# light_adaptation: 光適應，0表示全局，1表示局部。預設 1.0
# color_adaptation: 色彩適應。預設 0.0
reinhard_tonemap = cv2.createTonemapReinhard(gamma=2.2, intensity=0.0)

# 處理 HDR 影像
ldr_reinhard = reinhard_tonemap.process(hdr_image)

# 3. 轉換為 8-bit 整數影像以便顯示
# process() 的輸出是 [0, 1] 範圍的浮點數，需要乘以 255
ldr_reinhard_8bit = np.clip(ldr_reinhard * 255, 0, 255).astype(np.uint8)

print(f"\n色調映射後 LDR 影像的數值範圍: min={ldr_reinhard.min():.2f}, max={ldr_reinhard.max():.2f}")
print(f"色調映射後 LDR 影像的資料類型: {ldr_reinhard.dtype}")


# 4. 顯示結果
# 直接顯示HDR會因為數值範圍問題而失真
plt.figure(figsize=(12, 8))
plt.subplot(2, 1, 1)
# 為了勉強顯示HDR，我們對其進行log壓縮和歸一化
hdr_display = np.log1p(hdr_image)
hdr_display = (hdr_display - hdr_display.min()) / (hdr_display.max() - hdr_display.min())
plt.imshow(hdr_display)
plt.title("模擬的 HDR 影像 (經Log壓縮後勉強顯示)")

plt.subplot(2, 1, 2)
# Matplotlib 顯示順序是 RGB，我們創建時就是RGB順序，所以不用轉
plt.imshow(ldr_reinhard_8bit)
plt.title("經過 Reinhard Tonemapping 處理後的 LDR 影像")
plt.show()
```
