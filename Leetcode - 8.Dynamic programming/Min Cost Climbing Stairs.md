使用最小花費爬樓梯 Min Cost Climbing Stairs

LeetCode 746 / LintCode 1054 给你一个整数数组 `cost` ，其中 `cost[i]` 是从楼梯第 `i` 个台阶向上爬需要支付的费用。一旦你支付此费用，即可选择向上爬一个或者两个台阶。 你可以选择从下标为 `0` 或下标为 `1` 的台阶开始爬楼梯。 请你计算并返回达到楼梯顶部的最低花费（注意：楼梯顶部是下标 `n`，即越过数组最后一个元素 `n - 1`）。

**样例 1：** 输入：
```Python
cost = [10, 15, 20]
```

输出：
```Python
15
```

解释： 你将从下标为 1 的台阶开始。 - 支付 15 ，向上爬两个台阶，到达楼梯顶部。 总花费为 15 。

**样例 2：** 输入：
```Python
cost = [1, 100, 1, 1, 1, 100, 1, 1, 100, 1]
```

输出：
```Python
6
```

解释： 你将从下标为 0 的台阶开始。 - 支付 1 ，向上爬两个台阶，到达下标为 2 的台阶。 - 支付 1 ，向上爬两个台阶，到达下标为 4 的台阶。 - 支付 1 ，向上爬两个台阶，到达下标为 6 的台阶。 - 支付 1 ，向上爬一个台阶，到达下标为 7 的台阶。 - 支付 1 ，向上爬两个台阶，到达下标为 9 的台阶。 - 支付 1 ，向上爬一个台阶，到达楼梯顶部。 总花费为 6 。

**样例 3：** 输入：
```Python
cost = [0, 0, 1, 1]
```

输出：
```Python
1
```

解释： 从下标 1 开始支付 0 爬两步到下标 3，再支付 1 爬一步到顶部，总花费为 1

```Python
# 解法一：動態規劃一維陣列 (Bottom-Up DP - O(n) 空間)
class Solution:
    def minCostClimbingStairs(self, cost: list[int]) -> int:
        n = len(cost)
        # dp[i] 表示到達第 i 階台階所需的最低花費（樓頂為第 n 階）
        dp = [0] * (n + 1)
        # 可以直接從下標 0 或 1 出發，因此到達這兩階的花費為 0
        dp[0] = 0
        dp[1] = 0

        for i in range(2, n + 1):
            dp[i] = min(dp[i - 1] + cost[i - 1], dp[i - 2] + cost[i - 2])

        return dp[n]
```


```Python
# 解法二：動態規劃滾動變數 (O(1) 空間優化 - 最優解)
class Solution:
    def minCostClimbingStairs(self, cost: list[int]) -> int:
        # prev_two 代表 dp[i - 2]，prev_one 代表 dp[i - 1]
        prev_two, prev_one = 0, 0

        for i in range(2, len(cost) + 1):
            curr = min(prev_one + cost[i - 1], prev_two + cost[i - 2])
            prev_two = prev_one
            prev_one = curr

        return prev_one
```

解釋: step1: 狀態定義 `dp[i]` 為到達第 `i` 階台階的最低累計花費，由於樓頂在陣列之外，目標是求 `dp[n]`（`n = len(cost)`）。 step2: Base Case 為 `dp[0] = 0` 與 `dp[1] = 0`（題目允許免費從第 0 階或第 1 階起跳，離開該階時才需支付 `cost[i]`）。 step3: 以样例 1 `cost = [10, 15, 20]` 為例，`n = 3`，初始化 `prev_two = 0`（`dp[0]`），`prev_one = 0`（`dp[1]`）。 step4: `i = 2`（計算到達第 2 階的最低花費）： - 從第 1 階爬 1 步：`prev_one + cost[1] = 0 + 15 = 15` - 從第 0 階爬 2 步：`prev_two + cost[0] = 0 + 10 = 10` - 取較小值 `curr = min(15, 10) = 10`，更新 `prev_two = 0, prev_one = 10`。 step5: `i = 3`（計算到達第 3 階樓頂的最低花費）： - 從第 2 階爬 1 步：`prev_one + cost[2] = 10 + 20 = 30` - 從第 1 階爬 2 步：`prev_two + cost[1] = 0 + 15 = 15` - 取較小值 `curr = min(30, 15) = 15`，更新 `prev_two = 10, prev_one = 15`。 step6: 迴圈結束，最終回傳 `prev_one = 15`。

解釋: 考慮到達第 `i` 階台階的最後一步是從第 `i - 1` 階爬 1 步上來，還是從第 `i - 2` 階爬 2 步上來。 最低花費 `Dp[i] = min(Dp[i - 1] + cost[i - 1], Dp[i - 2] + cost[i - 2])`。 本題是 **爬樓梯（LintCode 111 / LeetCode 70）的帶權重求最小值版本**，轉移結構完全相同，只是將「方案數相加」改為「花費取最小值」。

### **LeetCode 746 / LintCode 1054 - Min Cost Climbing Stairs（使用最小花費爬樓梯）**

這道題目是經典的 **一維線性動態規劃（1D Linear DP）** 問題，也是「爬樓梯（Climbing Stairs）」最直接的進階變形。本題的核心考點在於 **釐清「到達第 `i` 階」與「從第 `i` 階起跳」的費用歸屬**，以及確認 **樓頂的真正位置是 `n` 而非 `n - 1`**。

## **解法解析**

這道題可以轉化為 **自底向上（Bottom-Up）的遞推關係式** 並配合滾動變數來求解。

### **思路**

1. **觀察規律（釐清題意邊界）**
    
    - 假設 `cost = [10, 15, 20]`，共有 3 階台階（下標 `0, 1, 2`）。
        
    - 「樓頂」是指跨過最後一階台階（下標 `2`）之後的位置，也就是 **下標 `3`（即 `n = len(cost)`）**。如果只停在下標 `2`，代表還沒爬完樓梯！
        
    - 題目規定可以選擇從下標 `0` 或 `1` 開始，這意味著 **站在下標 `0` 或 `1` 上本身不花錢（`dp[0] = 0, dp[1] = 0`）**，只有當你決定「從第 `i` 階往上跳」時，才需要支付 `cost[i]`。
        
2. **發現遞推公式**
    
    - 要到達第 `i` 階，只有兩條路：
        
        - 先到達第 `i - 1` 階（花費 `dp[i - 1]`），再支付 `cost[i - 1]` 往上爬 1 步。
            
        - 先到達第 `i - 2` 階（花費 `dp[i - 2]`），再支付 `cost[i - 2]` 往上爬 2 步。
            
    - 因此遞推公式為：
        
        - `dp[i] = min(dp[i - 1] + cost[i - 1], dp[i - 2] + cost[i - 2])`
            
    - 初始條件：
        
        - `dp[0] = 0`
            
        - `dp[1] = 0`
            
3. **代碼執行流程**
    
    - 初始化兩個滾動變數 `prev_two = 0`（代表 `dp[i - 2]`）和 `prev_one = 0`（代表 `dp[i - 1]`）。
        
    - 迴圈 `i` 從 `2` 遍歷到 `len(cost)`（包含 `n` 樓頂）。
        
    - 每次計算 `curr = min(prev_one + cost[i - 1], prev_two + cost[i - 2])`，隨後將 `prev_two` 與 `prev_one` 向前滾動更新。
        
    - 迴圈結束後返回 `prev_one`，即為到達樓頂 `dp[n]` 的最低花費。
        

## **具體舉例**

假設 `cost = [1, 100, 1, 1, 1, 100, 1, 1, 100, 1]`（`n = 10`），到達每一階台階的最低花費 `dp[i]` 演變過程如下：

|**目標台階 i**|**cost[i]（離開此階費用）**|**來源 1：dp[i-1] + cost[i-1]**|**來源 2：dp[i-2] + cost[i-2]**|**dp[i]（到達第 i 階最低花費）**|
|---|---|---|---|---|
|`0`|`1`|Base Case|Base Case|`0`|
|`1`|`100`|Base Case|Base Case|`0`|
|`2`|`1`|`0 + 100 = 100`|`0 + 1 = 1`|`1`|
|`3`|`1`|`1 + 1 = 2`|`0 + 100 = 100`|`2`|
|`4`|`1`|`2 + 1 = 3`|`1 + 1 = 2`|`2`|
|`5`|`100`|`2 + 1 = 3`|`2 + 1 = 3`|`3`|
|`6`|`1`|`3 + 100 = 103`|`2 + 1 = 3`|`3`|
|`7`|`1`|`3 + 1 = 4`|`3 + 100 = 103`|`4`|
|`8`|`100`|`4 + 1 = 5`|`3 + 1 = 4`|`4`|
|`9`|`1`|`4 + 100 = 104`|`4 + 1 = 5`|`5`|
|`10`（樓頂）|-|`5 + 1 = 6`|`4 + 100 = 104`|**`6`**|

最後返回 `dp[10] = 6`，表示到達樓頂的最低總花費為 **6**。

## **時間與空間複雜度分析**

- **時間複雜度：O(n)**（其中 `n` 為陣列 `cost` 的長度）
    
    - 只需從 `2` 到 `n` 單次遍歷陣列，每次狀態轉移為 `O(1)` 計算，因此時間複雜度為 **O(n)**。
        
- **空間複雜度：O(1)**
    
    - 透過兩個滾動變數 `prev_two` 和 `prev_one` 取代長度為 `n + 1` 的 `dp` 陣列，僅需常數額外空間，因此空間複雜度為 **O(1)**。
        

## **其他解法**

### **1. 原地修改陣列（In-Place Bottom-Up DP）**

- **思路**：
    
    - 換一種狀態定義：令 `cost[i]` 直接表示「**踩上第 `i` 階並從第 `i` 階起跳**」所需的累計最低花費。
        
    - 從 `i = 2` 遍歷到 `n - 1`，更新 `cost[i] += min(cost[i - 1], cost[i - 2])`。
        
    - 最後到達樓頂可以從 `n - 1` 跨 1 步或從 `n - 2` 跨 2 步，因此回傳 `min(cost[-1], cost[-2])`。
        
- **時間複雜度**：O(n)
    
- **空間複雜度**：O(1)（但會修改原始輸入陣列，面試中通常建議先詢問面試官是否允許修改輸入）
    

### **2. 記憶化搜索（Top-Down DP / DFS + Memo）**

- **思路**：
    
    - 定義 `dfs(i)` 為到達第 `i` 階所需的最低花費。
        
    - 當 `i <= 1` 時回傳 `0`；否則計算 `min(dfs(i - 1) + cost[i - 1], dfs(i - 2) + cost[i - 2])` 並存入雜湊表或陣列 `memo[i]`。主程式呼叫 `dfs(len(cost))`。
        
- **時間複雜度**：O(n)
    
- **空間複雜度**：O(n)（遞迴呼叫棧與記憶化快取空間）
    

## **總結**

- **最直觀的解法**：**一維陣列 DP（`dp = [0] * (n + 1)`）**，狀態含義明確，不易在邊界條件出錯，時間 `O(n)`，空間 `O(n)`。
    
- **最佳解法（面試首選）**：**O(1) 空間滾動變數 DP**，不破壞原始輸入陣列，且時間 `O(n)`、空間 `O(1)` 達到理論最優。
    
- **常見易錯點**：
    
    - **誤把 `n - 1` 當作樓頂**：若直接回傳 `dp[n - 1]`，會變成「只走到最後一階但還沒跨上去」，少算了從 `n - 1` 跨出最後一步的 `cost[n - 1]`（或從 `n - 2` 直接跨兩步跳過 `n - 1` 的情況）。正確終點必須是 `dp[n]`（或 `min(dp[n - 1] + cost[n - 1], dp[n - 2] + cost[n - 2])`）。
        
    - **初始化誤設為 `dp[0] = cost[0], dp[1] = cost[1]`**：若這樣定義，代表 `dp[i]` 是「踩上第 `i` 階並支付費用後的累計花費」，則最後回傳值必須寫成 `min(dp[n - 1], dp[n - 2])` 才能對應正確！兩種狀態定義只要首尾一致即可，切勿混用。

### **延伸變形題：打家劫舍（LeetCode 198）- 從「跨 1 或 2 步求最小花費」變成「相鄰不可選求最大收益」**

你是一个专业的小偷，计划偷窃沿街的房屋。每间房内都藏有一定的现金，影响你偷窃的唯一制约因素就是相邻的房屋装有相互连通的防盗系统，**如果两间相邻的房屋在同一晚上被小偷闯入，系统会自动报警**。给定一个代表每个房屋存放金额的非负整数数组，计算你 **不触动警报装置的情况下** ，一夜之内能够偷窃到的最高金额。

Python

```
class Solution:
    def rob(self, nums: list[int]) -> int:
        # 同样只需维护前两个状态：prev_two 代表 dp[i-2]，prev_one 代表 dp[i-1]
        prev_two, prev_one = 0, 0

        for num in nums:
            # 决定第 i 间房偷或不偷：
            # 1. 不偷：最高收益维持 prev_one (dp[i-1])
            # 2. 偷：  最高收益为 prev_two + num (dp[i-2] + nums[i])
            curr = max(prev_one, prev_two + num)
            prev_two = prev_one
            prev_one = curr

        return prev_one
```
