
LeetCode 134 / LintCode 187 在一条环路上有 `n` 个加油站，其中第 `i` 个加油站有汽油 `gas[i]` 升。你有一辆油箱容量无限的汽车，从第 `i` 个加油站开往第 `i+1` 个加油站需要消耗汽油 `cost[i]` 升。你从其中的一个加油站出发，开始时油箱为空。给定两个整数数组 `gas` 和 `cost` ，如果你可以按顺序绕环路行驶一周，则返回出发时加油站的编号，否则返回 `-1` 。如果存在解，则 **保证** 它是 **唯一** 的。

**样例 1：** 输入：
```Python
gas = [1, 2, 3, 4, 5]
cost = [3, 4, 5, 1, 2]
```

输出：
```Python
3
```

解释： 从 3 号加油站（索引为 3 处）出发，可获得 4 升汽油。此时油箱有 = 0 + 4 = 4 升汽油 开往 4 号加油站，此时油箱有 4 - 1 + 5 = 8 升汽油 开往 0 号加油站，此时油箱有 8 - 2 + 1 = 7 升汽油 开往 1 号加油站，此时油箱有 7 - 3 + 2 = 6 升汽油 开往 2 号加油站，此时油箱有 6 - 4 + 3 = 5 升汽油 开往 3 号加油站，你需要消耗 5 升汽油，正好足够你返回到 3 号加油站。 因此，3 可为起始索引。

**样例 2：** 输入：
```ython
gas = [2, 3, 4]
cost = [3, 4, 3]
```

输出：
```Python
-1
```

解释： 你不能从 0 号或 1 号加油站出发，因为没有足够的汽油可以让你行驶到下一个加油站。 我们从 2 号加油站出发，可以获得 4 升汽油。此时油箱有 = 0 + 4 = 4 升汽油 开往 0 号加油站，此时油箱有 4 - 3 + 2 = 3 升汽油 开往 1 号加油站，此时油箱有 3 - 3 + 3 = 3 升汽油 你无法返回 2 号加油站，因为返程需要消耗 4 升汽油，但是你的油箱只有 3 升汽油。 因此，无论怎样，你都不可能绕环路行驶一周。

**样例 3：** 输入：
```Python
gas = [5, 1, 2, 3, 4]
cost = [4, 4, 1, 5, 1]
```

输出：
```Python
4
```

解释： 总油量 `5+1+2+3+4 = 15` 恰好等于总耗油量 `4+4+1+5+1 = 15`，只有从索引 4 出发才能全程保持油箱不出现负数并绕行一周。


```Python
# 解法一：貪心法（一次遍歷同時維護總油量差與當前油箱油量，最優解）
def canCompleteCircuit(self, gas: list[int], cost: list[int]) -> int:
    total_tank = 0  # 記錄整圈的總淨油量（總加油 - 總耗油）
    curr_tank = 0   # 記錄從當前候選起點出發後的剩餘油量
    start = 0       # 候選起點索引

    for i in range(len(gas)):
        diff = gas[i] - cost[i]
        total_tank += diff
        curr_tank += diff

        # 若油箱見底（小於 0），代表從 start 到 i 之間的任何站點都不能作為起點
        if curr_tank < 0:
            start = i + 1
            curr_tank = 0

    return start if total_tank >= 0 else -1
```


```Python
# 解法二：貪心法（NeetCode 經典先檢查總油量寫法）
def canCompleteCircuit(self, gas: list[int], cost: list[int]) -> int:
    if sum(gas) < sum(cost):
        return -1

    total = 0
    res = 0
    for i in range(len(gas)):
        total += (gas[i] - cost[i])
        if total < 0:
            total = 0
            res = i + 1
    return res
```

解釋（以解法一為例）: step1: 計算每個站點的淨油量變化 `diff = gas[i] - cost[i]`，以 `gas = [1, 2, 3, 4, 5], cost = [3, 4, 5, 1, 2]` 為例，淨油量陣列為 `[-2, -2, -2, +3, +3]` step2: 初始化 `total_tank = 0`、`curr_tank = 0`、`start = 0` step3: `i = 0`，`curr_tank` 變成 `-2`（小於 0），代表索引 0 無法到達索引 1，將候選起點設為 `start = 1`，`curr_tank` 歸零 step4: `i = 1` 與 `i = 2` 時，`curr_tank` 同樣變為 `-2`（小於 0），因此 `start` 依序被推進到 `2`，再推進到 `3` step5: `i = 3`，`curr_tank` 變成 `+3`；`i = 4`，`curr_tank` 累積為 `+6`，期間未再小於 0，`start` 保持在 `3` step6: 遍歷結束後檢查 `total_tank` 為 `0`（大於等於 0），代表總油量足夠跑完全程，直接回傳 `start = 3`

解釋（以解法二為例）: 先用 `sum(gas) < sum(cost)` 判斷整圈的總汽油是否連總消耗都達不到，若不足直接回傳 `-1`。若總油量足夠，題目保證一定存在唯一解，接著只需從左往右累加淨油量，一旦累加值掉到 `0` 以下，就把起點重置為下一個位置 `i + 1`，最後留下的 `res` 必然是唯一合法起點。

### **LeetCode 134 / LintCode 187 - Gas Station（加油站）**

這道題目是 NeetCode 150 中 **Greedy（貪心演算法）** 的經典高頻面試題。暴力模擬每個起點需要 `O(n²)` 時間，但只要透過兩個關鍵的數學性質，就能將時間複雜度壓縮到線性的 **`O(n)`**。

## **解法解析**

這道題的核心在於把「環形繞圈模擬」轉化為 **「淨油量差值陣列的區間排除」** 來求解。

### **思路**

1. **觀察規律（兩大核心定理）**
    
    - **定理一（全域可行性）**：如果所有加油站的總油量小於總耗油量，即 `sum(gas) < sum(cost)`，那麼無論從哪裡出發都不可能繞完一圈，必回傳 `-1`；反之，**只要 `sum(gas) >= sum(cost)`，環路上就一定存在至少一個合法起點**。
        
    - **定理二（局部排除性 / 斷點跳躍）**：假設你從起點 `start` 出發，一路累加淨油量 `gas[k] - cost[k]`，直到第 `i` 站時油箱首次變成負數（`curr_tank < 0`）。
        
        - 這代表從 `start` 無法開過第 `i` 站。
            
        - 更關鍵的是：**介於 `start` 和 `i` 之間的任何一個站點 `m`（`start < m <= i`），也絕對不可能作為起點開過第 `i` 站**！
            
        - 原因：因為你能從 `start` 開到 `m`，代表抵達 `m` 時油箱裡的剩餘油量一定大於等於 `0`。連帶著「大於等於 `0` 的餘油」從 `m` 出發都會在 `i` 站沒油，若直接從 `m` 以「空油箱（`0` 升）」出發，油量只會更少，必然更早見底。
            
        - 因此，一旦在 `i` 站斷油，可以直接把 `[start, i]` 整段區間全部排除，下一個候選起點直接跳到 `i + 1`。
            
2. **發現核心判斷邏輯**
    
    - 維護 `total_tank += gas[i] - cost[i]` 判斷整圈總油量是否夠用。
        
    - 維護 `curr_tank += gas[i] - cost[i]` 追蹤當前區間是否斷油。
        
    - 一旦 `curr_tank < 0`，立刻重置 `start = i + 1` 並將 `curr_tank = 0`。
        
    - 為什麼遍歷到陣列末尾 `n - 1` 就結束，不用真的繞回前面檢查？因為只要 `total_tank >= 0`，後半段累積的正餘油一定足以填補前半段虧損的負油量。
        
3. **代碼執行流程**
    
    - 單次 `for` 迴圈從 `0` 走到 `n - 1`。
        
    - 同步更新 `total_tank` 與 `curr_tank`。
        
    - 遇到負油量就將起點右移到 `i + 1` 並清空當前油箱。
        
    - 迴圈結束後依據 `total_tank >= 0` 回傳 `start` 或 `-1`。
        

## **具體舉例**

假設 `gas = [1, 2, 3, 4, 5]`，`cost = [3, 4, 5, 1, 2]`，變數變化如下：

|**i**|**gas[i]**|**cost[i]**|**diff (gas - cost)**|**total_tank**|**curr_tank**|**判斷 curr_tank < 0**|**start 變化**|**狀態說明**|
|---|---|---|---|---|---|---|---|---|
|初始化|-|-|-|`0`|`0`|-|`0`|假設從 0 號站出發|
|`i = 0`|`1`|`3`|`-2`|`-2`|`-2` -> `0`|**True**|`0 -> 1`|0 號站到不了 1 號站，起點改為 1|
|`i = 1`|`2`|`4`|`-2`|`-4`|`-2` -> `0`|**True**|`1 -> 2`|1 號站到不了 2 號站，起點改為 2|
|`i = 2`|`3`|`5`|`-2`|`-6`|`-2` -> `0`|**True**|`2 -> 3`|2 號站到不了 3 號站，起點改為 3|
|`i = 3`|`4`|`1`|`+3`|`-3`|`+3`|False|`3`|3 號站出發淨賺 3 升油，順利通過|
|`i = 4`|`5`|`2`|`+3`|`0`|`+6`|False|`3`|4 號站再淨賺 3 升油，順利通過|

遍歷結束後，`total_tank = 0`（大於等於 0），返回最終的 `start = 3`。

## **時間與空間複雜度分析**

- **時間複雜度：O(n)**
    
    - 只需對長度為 `n` 的陣列進行一次線性掃描（解法二為兩次線性掃描，漸進複雜度同樣為 `O(n)`），每個索引只會被訪問一次，時間複雜度為 **O(n)**。
        
- **空間複雜度：O(1)**
    
    - 只使用了 `total_tank`、`curr_tank`、`start` 等常數個變數，沒有建立額外的陣列或雜湊表，空間複雜度為 **O(1)**。
        

## **其他解法**

### **1. 暴力模擬法（Brute Force）**

- **思路**：
    
    - 枚舉每一個站點 `start`（`0` 到 `n - 1`）作為起點，利用取餘數 `(start + step) % n` 模擬繞行一圈的過程，檢查途中油箱是否會小於 `0`。
        
- **優缺點**：
    
    - 直觀好寫，但在極端測資（例如 `gas = [0, 0, ..., 0, 1]`, `cost = [0, 0, ..., 1, 0]`）下會退化到每次都跑到最後一站才失敗，導致超時（TLE）。
        
- **時間複雜度**：O(n²)
    
- **空間複雜度**：O(1)
    

### **2. 折線圖最低點法（Minimum Prefix Sum）**

- **思路**：
    
    - 把從 `0` 出發的累積淨油量畫成折線圖。無論從哪一站出發，整條折線的相對高低起伏形狀都不會改變，只是整條線上下平移。
        
    - 只要整圈總油量 `total_tank >= 0`，我們只需要找到累積淨油量**最低點（虧損最嚴重的位置 `min_idx`）**，將它的**下一站 `(min_idx + 1) % n`** 作為起點，就相當於把最低點抬升到水平線 `0` 之上，保證全程不低於 `0`。
        
- **時間複雜度**：O(n)
    
- **空間複雜度**：O(1)
    

## **總結**

- **面試最推薦解法**：**一次遍歷貪心演算法（Greedy）**，時間 `O(n)`，空間 `O(1)`，邏輯簡潔且一次走訪即可完成。
    
- **面試必考追問**：面試官很常問「**為什麼在 `i` 站沒油時，不需要回頭檢查 `start + 1` 到 `i` 之間的站點？**」
    
    - 回答關鍵：因為從 `start` 能走到中間站 `k`，代表到達 `k` 時餘油大於等於 `0`；帶著額外餘油都過不了 `i`，空油箱從 `k` 出發更不可能過得去。
        
- **核心思維**：環形問題若直接模擬容易陷入 `O(n²)`，透過「局部不可達則整段排除」的貪心策略即可降維成 `O(n)`。

### **進階變形：尋找「所有」合法起點（不保證唯一解）**

如果題目改為：環路上可能存在**多個**合法起點，請回傳**所有**可以繞環路行駛一週的加油站索引列表（利用「折線圖最低點」思想）：

Python

```
class Solution:
    def findAllValidStarts(self, gas: list[int], cost: list[int]) -> list[int]:
        n = len(gas)
        curr_tank = 0
        min_tank = float('inf')

        # 1. 從索引 0 模擬繞一圈，找出過程中的最低油量水平線 min_tank
        for i in range(n):
            curr_tank += gas[i] - cost[i]
            min_tank = min(min_tank, curr_tank)

        # 若整圈總淨油量小於 0，無任何合法起點
        if curr_tank < 0:
            return []

        # 2. 從後往前推算，只要把某站作為起點能讓最低點抬升至 >= 0，該站即為合法起點
        res = []
        for i in range(n - 1, -1, -1):
            if min_tank >= 0:
                res.append((i + 1) % n)
            min_tank -= (gas[i] - cost[i])

        return sorted(res)
```
