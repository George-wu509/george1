在 LintCode 64 / LeetCode 88（Merge Sorted Array）中，**`m`** 代表陣列 `A` 中原本存在的**有效元素數量**，而 **`n`** 代表陣列 `B` 的**總元素數量**。陣列 `A` 的真實記憶體容量大小為 $m + n$，其中後半段的 $n$ 個位置是預留給合併使用的空白空間。

直覺解法「看起來不像原地修改（In-place）」的原因在於：如果從陣列開頭（由小到大、由左至右）進行比較並寫入 `A`，會把 `A` 還沒被比較到的元素覆蓋掉，進而被迫開立一個額外陣列來暫存資料，空間複雜度變成 $O(m + n)$。

### 真正的原地修改原理：雙指標由後往前（From Right to Left）

由於陣列 `A` 的末端（索引 $m$ 至 $m + n - 1$）本來就是留空的，從右向左（由大到小）填充不會覆蓋任何尚未處理的有效資料：

1. **設定三個指標**：
    - 指標 `i = m - 1`：指向 `A` 的最後一個有效元素。
    - 指標 `j = n - 1`：指向 `B` 的最後一個元素。
    - 指標 `k = m + n - 1`：指向 `A` 的最後一個可用空間位置（最右端）。
        
2. **比較與填入**：
    - 每次比較 `A[i]` 與 `B[j]`，將較大者放入 `A[k]`，並將對應指標與 `k` 同步向左移動一位。
        
3. **邊界處理**：
    - 若 `B` 先處理完（`j < 0`），合併即結束（`A` 剩餘的前半段元素原本就已在正確位置）。
    - 若 `A` 的有效元素先處理完（`i < 0`），則將 `B` 剩餘的元素依序填入 `A` 前半段。

```python
class Solution:

    def merge(self, A: list[int], m: int, B: list[int], n: int) -> None:
        i = m - 1
        j = n - 1
        k = m + n - 1

        # 由後往前比較，將較大者放入 A[k]
        while i >= 0 and j >= 0:
            if A[i] > B[j]:
                A[k] = A[i]
                i -= 1
            else:
                A[k] = B[j]
                j -= 1
            k -= 1

        # 若 B 還有剩餘元素，填入 A 的剩餘空間
        while j >= 0:
            A[k] = B[j]
            j -= 1
            k -= 1
```

採用「雙指標由後往前」的核心原因，是為了**利用陣列 `A` 末端預留的空白空間，在不覆蓋未讀資料的前提下，實現真正的 $O(1)$ 原地修改（In-place）與 $O(m+n)$ 最優時間複雜度**。

### 一、為什麼「由前往後」不行？

假設 $A = [4, 5, 6, \_, \_, \_]$（$m=3$），$B = [1, 2, 3]$（$n=3$）。

若嘗試由前往後（從小到大）比較並寫入：

1. 比較 $A[0]=4$ 與 $B[0]=1$，發現 $1 < 4$。
    
2. 我們必須把較小的 $1$ 填入 $A[0]$。
    
3. **資料被覆蓋**：原本存放在 $A[0]$ 的有效資料 $4$ 直接被沖掉丟失！
    

為了避免覆蓋，由前往後只剩下兩種補救方式，但都有嚴重缺陷：

- **補救方案 A（複製陣列）**：先開一個長度為 $m$ 的新陣列把 $A$ 的原本內容存起來。
    
    - ❌ **缺點**：空間複雜度變成 $O(m)$，違反了題目要求「不使用額外陣列、原地修改」的本意。
        
- **補救方案 B（每次插入往後搬移）**：把 $1$ 寫入 $A[0]$ 前，先把 $A$ 現有的元素 $[4, 5, 6]$ 全部向右挪動一位。
    
    - ❌ **缺點**：每次搬移都需要 $O(m)$ 時間，整體時間複雜度暴增到 $O(m \times n)$，效率極差。
        

### 二、為什麼「由後往前」是最佳解？

「由後往前（從大到小）」能完美解決上述問題，優勢體現在兩個層面：

#### 1. 寫入位置永遠是安全的廢棄空間

陣列 `A` 的最右側（索引 $m$ 到 $m+n-1$）本來就是留給合併用的空白區域。當我們從最大值開始比較，並把較大者填入 `A` 的最右端時，最先被寫入的地方**絕對不會有尚未讀取的有效資料**。

#### 2. 數學上的不覆蓋保證 ($k \ge i$)

設定三個指標：

- $i = m - 1$（`A` 的未讀取資料最右端）
    
- $j = n - 1$（`B` 的未讀取資料最右端）
    
- $k = m + n - 1$（`A` 當前的寫入位置）
    

在演算法執行的任一時刻，寫入指標與讀取指標滿足關係式：

$$k = i + j + 1$$

因為 $B$ 陣列尚未處理完時 $j \ge 0$，所以：

$$k \ge i + 1 > i$$

這證明了**寫入指標 $k$ 永遠在讀取指標 $i$ 的右邊**。即使後期 `A` 內部的有效資料區被 $k$ 寫入，被覆蓋的位置也是「已經被讀取並搬移完畢的舊資料」，絕不會發生「未讀資料被寫入覆蓋」的情況。

### 三、三種解法綜合比較

| **解題思維**        | **時間複雜度**       | **空間複雜度**  | **能否原地修改（In-place）** | **評價**               |
| --------------- | --------------- | ---------- | -------------------- | -------------------- |
| **由前往後（複製舊 A）** | $O(m+n)$        | $O(m)$     | 否                    | 直覺但耗費空間              |
| **由前往後（插入右移）**  | $O(m \times n)$ | $O(1)$     | 是                    | 空間省但時間太慢             |
| **由後往前（雙指標）**   | **$O(m+n)$**    | **$O(1)$** | **是**                | **時間與空間均達理論極限（最優解）** |
