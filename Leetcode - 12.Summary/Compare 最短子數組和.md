1. **LintCode 406 的關鍵在於「全正數」**：因為數值具備單調性，雙指針左右邊界只需要各自向右掃描一次，就能以 **$O(N)$ 時間與 $O(1)$ 空間** 找到最優解。

Leetcode 406 [[Minimum Size Subarray Sum]]
给定一个由 `n` 个<mark style="background: #FFF3A3A6;">正整数</mark>组成的数组和一个正整数 `s` ，请找出该数组中满足其和 ≥ s 的最小长度子数组
Example: [2,3,1,2,4,3], s = 7  -> 2  ([ 3,4 ])
最佳解法:  雙指針 / 滑動窗口
```python
class Solution:

    def minimum_size(self, nums: List[int], s: int) -> int:
        if nums is None or len(nums) == 0:
            return -1

        n = len(nums)
        minLength = n + 1
        sum = 0
        j = 0
        for i in range(n):
            while j < n and sum < s:
                sum += nums[j]
                j += 1
            if sum >= s:
                minLength = min(minLength, j - i)
            sum -= nums[i]
            
        if minLength == n + 1:
            return -1
            
        return minLength
```
解釋: 
用雙指針(滑動視窗), 第一個指針i是左邊(i是左指針用for loop), 第二個指針j是右邊
1. 第一個指針i從左(id=0)一步步for loop移到右. 從一開始i在0的位置, 第二個指針j 也從id=0開始慢慢往右直到並計算sum直到sum>s. 紀錄長度=minLength
2. 第一個指針i往右移一步(id=1), sum減掉= id=0的值, 然後第二個指針j 從剛剛j停留的位置繼續往右移直到sum>s. 紀錄長度=minLength = min(minLength, j-i)
3. 繼續直到第一個指針i到最右端, minLength就是最小長度


Leetcode 1507  [[Shortest Subarray with Sum at Least K]]
返回 `A` 的最短的非空连续子数组的**长度**，该子数组的和至少为 `K`
Example: [2,3,1,2,4,3], s = 7 -> 1
最佳解法:  前綴和 + 單調隊列
```python
from collections import deque
def shortest_subarray(self, a, k):
	mono_queue = deque([(0, -1)])
	shortest = float('inf')
	prefix_sum = 0
	for end in range(len(a)):
		prefix_sum += a[end]
		# pop left
		while mono_queue and prefix_sum - mono_queue[0][0] >= k:
			min_prefix_sum, index = mono_queue.popleft()
			shortest = min(shortest, end - index)
		# push right
		while mono_queue and mono_queue[-1][0] >= prefix_sum:
			mono_queue.pop()
		mono_queue.append((prefix_sum, end))
	
	if shortest == float('inf'):
		return -1
	return shortest
```
解釋: 
使用完全相同的結構描述 LeetCode 1507 的解法步驟：
1. **初始化 (Initialization)**
    - 初始化雙端隊列 `queue = [(0, -1)]` 存放 `(prefix_sum, index)` 元組。
    - 設定當前前綴和 `prefix_sum = 0`，全局最小長度 `min_len = infinity`。
2. **右邊界掃描與狀態更新 (Expand Right & Accumulate)**
    - 遍歷右邊界 `right`（0 到 $N-1$），將 `nums[right]` 累加至 `prefix_sum`。
3. **雙端剪枝與隊列維護 (Dual-ended Pruning & Queue Maintenance)**
    - **隊頭檢查（更新答案）**：當 `queue` 非空且 `prefix_sum - queue[0].sum >= K` 時：
        - 更新 `min_len = min(min_len, right - queue[0].index)`。
        - 彈出隊頭 `queue.popleft()`（該隊頭對後續更右側的位置而言長度必然更長，已無保留價值）。
    - **隊尾檢查（維護單調性）**：當 `queue` 非空且 `queue[-1].sum >= prefix_sum` 時：
        - 彈出隊尾 `queue.pop()`（當前點前綴和更小且位置更靠右，已完全支配隊尾元素）。
    - 將當前 `(prefix_sum, right)` 推入隊尾。
4. **返回結果 (Return)**
    - 遍歷結束後，若 `min_len` 未被更新則返回 `-1`，否則返回 `min_len`。


### 为什么 LintCode 406 的解法不能用于 1507？

在 **LintCode 406** 中，因为所有数字都是正数：
1. 当 `sum < s` 时，右指针 `j` 必须右移才能让 `sum` 变大。
2. 当 `sum >= s` 时，左指针 `i` 右移缩小窗口，`sum` 必然变小。

但在 **LintCode 1507** 中存在负数，这种单调性被破坏。
- 例如：`nums = [2, -1, 2], K = 3`
- 当窗口包含 `[2, -1]` 时，和为 `1 < 3`。
- 如果按照滑动窗口逻辑，右指针右移加入 `2`，窗口为 `[2, -1, 2]`，和为 `3 >= 3`，长度为 `3`。
- 但实际上最短的有效子数组是末尾的 `[2, -1, 2]` 吗？不是，如果看后半部分，其实 `[2]` 只有 2 不够，但原数组中后两项 `[-1, 2]` 和只有 1。如果数组是 `[-1, 4]`，最短子数组只是 `[4]`（长度 1），但滑动窗口无法正确贪心地收缩左边界。

### LintCode 1507 的正确解法：前缀和 + 单调队列

要解决含负数的问题，需要引入**前缀和数组 `P`**，其中 $P[i]$ 表示前 $i$ 项的和。 问题转化为：找到一对 $(i, j)$，满足 $j > i$ 且 $P[j] - P[i] \ge K$，同时使长度 $j - i$ 最小。

我们维护一个存储前缀和下标的**单调递增双端队列 `deque`**：
```python
from collections import deque
from typing import List

class Solution:
    def shortestSubarray(self, nums: List[int], k: int) -> int:
        n = len(nums)
        # 1. 计算前缀和数组 P
        P = [0] * (n + 1)
        for i in range(n):
            P[i + 1] = P[i] + nums[i]
            
        min_len = n + 1
        q = deque()  # 存储前缀和下标，保持对应的前缀和单调递增
        
        for j in range(n + 1):
            # 优化 1 (弹队头)：如果当前前缀和 P[j] - P[q[0]] >= k
            # 说明找到一个可行解 j - q[0]，更新 min_len
            # 之后更靠右的 j' 即使能与 q[0] 满足条件，长度也必然大于当前的解，所以 q[0] 弹出
            while q and P[j] - P[q[0]] >= k:
                min_len = min(min_len, j - q.popleft())
                
            # 优化 2 (弹队尾)：如果当前前缀和 P[j] <= P[q[-1]]
            # 说明当前点 j 的前缀和更小，且位置更靠右（更容易凑出更大的差值且长度更短）
            # 队尾的 q[-1] 已经完全被 j 替代，从队尾弹出
            while q and P[j] <= P[q[-1]]:
                q.pop()
                
            q.append(j)
            
        return min_len if min_len <= n else -1
```

### 快速決策樹（遇到 Subarray 題目時的思考順序）

1. **元素是否全為正數（或條件隨視窗擴大單調變嚴格）？**
    
    - **是** $\rightarrow$ 首選 **滑動視窗 (Two Pointers)**，空間 $O(1)$ 最優解（如 LintCode 406）。
        
2. **包含負數，且條件是「等於 $K$」或「$K$ 的倍數」？**
    
    - **是** $\rightarrow$ 首選 **前綴和 + Hash Map**。求「個數」存頻率（LC 560）；求「最長長度」只存最早出現的 index（LintCode 911）。
        
3. **包含負數，且條件是「大於等於 $K$ ($\ge K$)」？**
    
    - 求**最短**長度 $\rightarrow$ **前綴和 + 單調佇列 (Monotonic Queue)**（LintCode 1507）。
        
    - 求**最長**長度 $\rightarrow$ **前綴和 + 單調棧 (Monotonic Stack)**（經典題：LC 962 Maximum Width Ramp / LC 1124 Longest Well-Performing Interval）。
        
4. **包含負數，無條件限制單純求「最大/最小和」或「最大乘積」？**
    
    - **是** $\rightarrow$ **動態規劃 (Kadane's 演算法)**（LintCode 41、LC 152）。




#### 大於等於 K, 最短長度用單調佇列, 最長長度用單調棧
```
當遇到 Subarray 題目時且包含負數，且條件是大於等於 K, 我知道應該要使用前綴和搭配譬如單調佇列. 但為什麼求最短長度 -> 前綴和 + 單調佇列 (Monotonic Queue). 而求最長長度 -> 前綴和 + 單調棧 (Monotonic Stack)? 請具體舉例說明並解釋單調佇列or單調棧是用來儲存甚麼? 所以是跟移除的順序或東西有關嗎?
```

這是一個非常核心且直擊演算法本質的問題。兩者之所以分別使用 **單調佇列 (Deque)** 和 **單調棧 (Stack)**，完全取決於「候選起點被淘汰（移除）的順序與原因」。

首先，把這兩類問題統一轉化為**前綴和 (Prefix Sum)** 的幾何問題：

定義 $P[i]$ 為前 $i$ 個元素的總和（$P[0] = 0$）。我們要找兩個下標 $i < j$，滿足：

$$P[j] - P[i] \ge K \quad \text{（即 } P[i] \le P[j] - K \text{）}$$
- $j$ 是子陣列的**終點**
- $i$ 是子陣列的**起點**（前一個位置）
- 子陣列的長度就是 **$j - i$**

無論求「最短」還是「最長」，我們在結構裡儲存的都是「有資格成為未來最佳起點的索引 $i$」**，而且這個結構裡面的 $P[i]$ 值**永遠保持嚴格單調遞增（因為如果有 $i_1 < i_2$ 且 $P[i_1] \ge P[i_2]$，那麼 $i_2$ 既比 $i_1$ 靠右、前綴和又更小，這在不同目標下會產生截然不同的淘汰邏輯）。

以下拆解這兩種情況的本質差異：

### 1. 求「最短」長度（$j - i$ 最小）$\rightarrow$ 前綴和 + 單調佇列 (Deque)

**代表題：** LintCode 1507 / LC 862 (Shortest Subarray with Sum at Least K)

#### 為什麼需要「兩端」都能移除（佇列 Deque）？

在求**最短**長度時，我們希望**起點 $i$ 越靠右（越大）越好**。結構中維護的是一個**單調遞增**的索引序列（越往右，$i$ 越大，$P[i]$ 也越大）：

1. **從「隊尾 (Back)」移除（維護單調性）：**
    
    當新的前綴和 $P[j]$ 進來時，如果發現隊尾的 $P[\text{back}] \ge P[j]$：
    
    - $j$ 比 $\text{back}$ 更靠右（距離未來的終點更近，長度更短），且 $P[j]$ 更小（更容易讓未來的 $P[\text{future}] - P[j] \ge K$ 成立）。
        
    - 因此，$\text{back}$ **在任何方面都被 $j$ 完爆**，直接從隊尾永久踢除。
        
2. **從「隊頭 (Front)」移除（已經配對成功，無須再留）：**
    
    當我們拿當前的 $P[j]$ 去檢查隊頭 $\text{front}$ 時，如果滿足 $P[j] - P[\text{front}] \ge K$：
    
    - 我們更新最短長度 `ans = min(ans, j - front)`。
        
    - **關鍵來了：** 因為 $j$ 還會繼續往右移動，未來出現的 $j' > j$ 就算也能和 $\text{front}$ 配對，算出来的長度 $j' - \text{front}$ **一定大於**現在的 $j - \text{front}$！
        
    - 既然 $\text{front}$ 已經找到了離它最近的合法終點 $j$，它這輩子不可能再貢獻更短的答案了，所以直接從**隊頭踢除 (`popleft`)**。
        

#### 具體舉例

假設陣列 `nums = [2, -1, 2]`，$K = 3$。

前綴和 `P = [0, 2, 1, 3]`（索引 $0, 1, 2, 3$）。

- **$j = 0$ ($P[0]=0$)**：Deque 放入 `0`。目前 Deque: `[0]` (對應值 `[0]`)
    
- **$j = 1$ ($P[1]=2$)**：$P[1] - P[0] = 2 < 3$。`2 > 0` 保持遞增，放入 `1`。目前 Deque: `[0, 1]` (對應值 `[0, 2]`)
    
- **$j = 2$ ($P[2]=1$)**：
    
    - 檢查隊頭：`P[2] - P[0] = 1 - 0 = 1 < 3`。
        
    - 檢查隊尾：`P[1]=2 >= P[2]=1`。索引 `1` 比 `2` 靠左、值又比 `2` 大，未來誰選 `1` 都不如選 `2`（更短且更容易達標），所以 **隊尾彈出 `1`**！
        
    - 放入 `2`。目前 Deque: `[0, 2]` (對應值 `[0, 1]`)
        
- **$j = 3$ ($P[3]=3$)**：
    
    - 檢查隊頭：`P[3] - P[0] = 3 - 0 = 3 >= 3`（達標！長度 `3 - 0 = 3`）。索引 `0` 的使命已完成，未來不會有比 `3` 更短的配對，**隊頭彈出 `0`**！
        
    - 繼續檢查新隊頭 `2`：`P[3] - P[2] = 3 - 1 = 2 < 3`（未達標，停止）。
        
    - 放入 `3`。目前 Deque: `[2, 3]`。
        
- 最終最短長度為 **3**。
    

### 2. 求「最長」長度（$j - i$ 最大）$\rightarrow$ 前綴和 + 單調棧 (Stack)

**代表題：** LC 1124 (Longest Well-Performing Interval，這題本質是元素為 `1` 和 `-1`，求總和 $\ge 1$ 的最長子陣列) / LC 962 (Maximum Width Ramp，條件為 $K=0$)

#### 為什麼只需要「單調棧 (Stack)」且分兩階段處理？

在求**最長**長度時，我們希望**起點 $i$ 越靠左（越小）越好**。

1. **為什麼「後進來的較大值」根本沒資格當起點？（單調遞減棧）**
    
    假設從左到右掃描前綴和，如果 $i_1 < i_2$ 且 $P[i_1] \le P[i_2]$：
    
    - 因為我們要的是**最長**長度，$i_1$ 比 $i_2$ 更靠左（長度更長），而且 $P[i_1]$ 更小（更容易滿足 $P[j] - P[i_1] \ge K$）。
        
    - 所以 **$i_2$ 永遠不可能比 $i_1$ 更好**！我們甚至不需要把 $i_2$ 放進結構裡。
        
    - 這意味著：從 $0$ 到 $N$ 掃描一遍，只有當 $P[i]$ **嚴格小於**目前棧頂的前綴和時，才壓入棧中。這樣一來，整個陣列的候選起點就固定下來了，形成一個**索引遞增、前綴和嚴格遞減的單調棧**。
        
2. **為什麼從「棧頂 (Top)」移除，而且是「從右往左」掃描終點 $j$？**
    
    建立好這個「候選起點棧」後，我們讓終點 $j$ **從陣列最右端（$N$）往左（$0$）倒序遍歷**：
    
    - 棧頂 (`top`) 存放的是**最靠右**（但前綴和最小）的候選起點。
        
    - 當在某個 $j$ 發現滿足 $P[j] - P[\text{top}] \ge K$ 時：
        
        - 我們記錄長度 `ans = max(ans, j - top)`。
            
        - **關鍵來了：** 因為 $j$ 接下來是**往左移動**（$j$ 會越來越小），未來遇到的 $j' < j$ 就算也能和 $\text{top}$ 配對，算出来的長度 $j' - \text{top}$ **一定小於**現在的 $j - \text{top}$！
            
        - 既然 $\text{top}$ 已經找到了離它最遠（最靠右）的合法終點 $j$，它也不可能再貢獻更長的答案了，直接從**棧頂彈出 (`pop`)**，繼續檢查下一個更靠左的棧頂元素！
            

#### 具體舉例

假設陣列 `nums = [1, -1, -1, 1, 1]`，求總和 $\ge 1$ ($K = 1$) 的最長子陣列。

前綴和 `P = [0, 1, 0, -1, 0, 1]`（索引 $0, 1, 2, 3, 4, 5$）。

- **第一步：從左到右建立「前綴和嚴格遞減」的單調棧（篩選合法起點）**
    
    - $i=0$ ($P[0]=0$)：入棧。Stack: `[0]`
        
    - $i=1$ ($P[1]=1$)：$1 > 0$，比 `0` 靠右且值更大，沒資格當起點，忽略。
        
    - $i=2$ ($P[2]=0$)：$0 \ge 0$，比 `0` 靠右且值沒更小，忽略。
        
    - $i=3$ ($P[3]=-1$)：$-1 < 0$，雖然靠右但前綴和創新低，入棧！Stack: `[0, 3]`
        
    - $i=4$ ($P[4]=0$)：$0 > -1$，忽略。
        
    - $i=5$ ($P[5]=1$)：$1 > -1$，忽略。
        
    - 候選起點鎖定為 Stack: `[0, 3]`（對應前綴和 `[0, -1]`）。
        
- **第二步：終點 $j$ 從右往左掃描，貪心彈出棧頂**
    
    - **$j = 5$ ($P[5]=1$)**：
        
        - 看棧頂 `3`：$P[5] - P[3] = 1 - (-1) = 2 \ge 1$（達標！長度 `5 - 3 = 2`）。索引 `3` 已經配對到最右邊的 `5` 了，**棧頂彈出 `3`**！
            
        - 看新棧頂 `0`：$P[5] - P[0] = 1 - 0 = 1 \ge 1$（達標！長度 `5 - 0 = 5`）。索引 `0` 也配對到最右邊的 `5` 了，**棧頂彈出 `0`**！
            
        - 棧已空，直接提前結束！
            
    - 最終最長長度為 **5**（整個陣列 `[1, -1, -1, 1, 1]`）。
        

### 核心差異總結對照

你的直覺完全正確，這完全是因為「淘汰無效起點的發生時機與位置」不同：

|**比較維度**|**求「最短」長度 (LC 862)**|**求「最長」長度 (LC 1124 / 962)**|
|---|---|---|
|**資料結構**|**單調佇列 (Deque)**|**單調棧 (Stack)**|
|**結構內前綴和趨勢**|從頭到尾 **單調遞增**|從底到頂 **單調遞減**|
|**掃描順序**|單趟：起點與終點同步 **從左到右**|兩趟：先 **從左到右** 建棧，終點再 **從右到左** 掃描|
|**何時淘汰「舊元素」？**<br><br>  <br><br>_(維持單調性)_|新元素進來時，把隊尾「較大」的舊元素踢掉（**從隊尾移除**），因為新元素更靠右且值更小。|建棧時，如果新元素比棧頂「大或等於」，**根本不入棧**，因為棧頂更靠左且值更小。|
|**何時淘汰「已配對元素」？**<br><br>  <br><br>_(貪心求極值)_|隊頭一旦配對成功，後續的 $j$ 只會更遠（長度變長），隊頭失去價值，**從隊頭移除**。|棧頂一旦配對成功，後續的 $j$ 只會更近（長度變短），棧頂失去價值，**從棧頂移除**。|
