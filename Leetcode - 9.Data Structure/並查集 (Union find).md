#### 詳細介紹並查集 (Union Find)
```
詳細介紹並查集 (Union Find)
```
**並查集 (Union Find，又稱 Disjoint Set)** 是一種極度巧妙且高效的資料結構，專門用來解決「連通性」**與**「群組劃分」的問題。

你可以把它想像成「黑幫火拼與合併」的過程： 每個人一開始都是獨立的個體（自己是自己的老大）。當兩個人結盟時，他們的「老大」會進行談判，最後其中一個老大會臣服於另一個老大，兩個幫派就此合併。未來要確認某兩個人是不是同一夥的，只要問他們的「最終老大」是不是同一個人就可以了。

它只有兩個核心操作：

1. **Find (尋找)**：尋找這個人所屬群組的「最終老大（根節點）」。
    
2. **Union (合併)**：將兩個人所屬的群組，透過老大的臣服，合併成同一個群組。

### 1. 具體例子與圖解：一步步看並查集運作

假設我們有 5 個人，編號 `0` 到 `4`。我們用一個陣列 `parent` 來記錄每個人的老大是誰。

**初始狀態 (每個人都是自己的老大)** 每個人自成一派，`parent` 陣列為 `[0, 1, 2, 3, 4]`。

Plaintext

```
[0]   [1]   [2]   [3]   [4]
```

**Step 1: 執行 `Union(1, 2)` (1 號和 2 號結盟)** 1 號和 2 號的老大分別是自己。現在讓 1 號當 2 號的老大。`parent` 陣列變成 `[0, 1, 1, 3, 4]`。

Plaintext

```
[0]     [1]     [3]     [4]
         |
        [2]
```

**Step 2: 執行 `Union(3, 4)` (3 號和 4 號結盟)** 讓 3 號當 4 號的老大。`parent` 陣列變成 `[0, 1, 1, 3, 3]`。

Plaintext

```
[0]     [1]             [3]
         |               |
        [2]             [4]
```

**Step 3: 執行 `Union(2, 4)` (2 號和 4 號結盟 - 幫派合併)** 這一步最關鍵！2 號和 4 號要結盟，**不能直接把 2 號連到 4 號身上**。 程式會先觸發 `Find`：

- `Find(2)` 發現 2 的老大是 1 號。
    
- `Find(4)` 發現 4 的老大是 3 號。 因為老大不同，所以讓 3 號臣服於 1 號。`parent` 陣列更新為 `[0, 1, 1, 1, 3]` (3 的老大變成 1)。
    

Plaintext

```
[0]           [1]
             /   \
           [2]   [3]
                  |
                 [4]
```

現在，如果我們執行 `Find(4)`，它會沿著路徑 `4 -> 3 -> 1` 找到最終老大是 `1`。只要 1 號到 4 號的人執行 `Find`，回傳的都是 `1`，代表他們都在同一個群組。

### 2. 並查集的兩大究極優化魔法

如果只是像上面那樣連來連去，最慘的情況下樹會變成「一條直線」（像是 Linked List），找老大的時間會退化成 $O(N)$。因此並查集有兩個必備的優化，能讓時間複雜度降到幾乎是 $O(1)$！

#### 魔法一：路徑壓縮 (Path Compression) —— 發生在 `Find` 時

當我們執行 `Find(4)` 找老大時，經過了 `4 -> 3 -> 1`。既然已經知道 4 的最終老大是 1，下次為什麼還要繞過 3 呢？ **作法：** 在 `Find` 的回傳過程中，順手把沿途經過的所有小弟，**直接認最終老大為直屬老大**。

執行 `Find(4)` 後的樹會被「壓扁」：

Plaintext

```
[0]           [1]
            /  |  \
          [2] [3] [4]   <-- 4 號直接連到 1 號！
```

下次再 `Find(4)` 時，只要 1 步就找到了。

#### 魔法二：按秩合併 (Union by Rank / Size) —— 發生在 `Union` 時

當兩個幫派要合併時，應該是「小幫派」臣服於「大幫派」（或是樹比較矮的連到樹比較高的底下），這樣合併後的樹才不會變太深。**作法：** 額外維護一個 `rank` 陣列記錄樹的高度，合併時永遠是 `rank` 小的指向 `rank` 大的。

### 3. Python 模板實作

這是 LeetCode 刷題中最標準、包含雙重優化的並查集模板，直接背下來可以秒殺所有連通性題目：

```python
class UnionFind:
    def __init__(self, size: int):
        # 初始時，每個人的老大都是自己
        self.parent = [i for i in range(size)]
        # rank 記錄這棵樹的高度（或大小），初始為 1
        self.rank = [1] * size

    def find(self, x: int) -> int:
        # 如果自己不是最終老大
        if self.parent[x] != x:
            # 【路徑壓縮】：遞迴尋找最終老大，並直接把自己的老大改成最終老大
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, x: int, y: int) -> bool:
        root_x = self.find(x)
        root_y = self.find(y)

        # 如果老大同一個，代表原本就在同一群組，不需要合併
        if root_x == root_y:
            return False

        # 【按秩合併】：矮樹接在高樹下面
        if self.rank[root_x] > self.rank[root_y]:
            self.parent[root_y] = root_x
        elif self.rank[root_x] < self.rank[root_y]:
            self.parent[root_x] = root_y
        else:
            # 如果兩棵樹一樣高，誰接誰都可以，但被接的高樹 rank 要 +1
            self.parent[root_y] = root_x
            self.rank[root_x] += 1
            
        return True
```

### 為什麼這東西這麼強？

利用並查集，每次 `Find` 和 `Union` 的平均時間複雜度為 $O(\alpha(N))$，其中 $\alpha$ 是反阿克曼函數 (Inverse Ackermann function)。在全宇宙能用到的資料量下，這個值都不會超過 `5`。因此，你可以把並查集的操作當作是**完美的常數時間 $O(1)$**。
