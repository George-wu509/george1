#### 詳細介紹平衡樹 (AVL樹) (Balanced Tree)
```
詳細介紹平衡樹 (AVL樹) (Balanced Tree)
```
**平衡樹 (Balanced Tree)**，尤其是其中最著名的 **AVL 樹 (Adelson-Velsky and Landis Tree)**，是為了解決「二元搜尋樹 (BST) 效能退化」而發明的一種極度自律的資料結構。

### 1. 為什麼需要平衡樹？(解決了什麼痛點)

在前幾次討論中我們提到，二元搜尋樹 (BST) 規定「左邊小、右邊大」。理想情況下，它的搜尋時間複雜度是極快的 $O(\log N)$。

**但 BST 有一個致命弱點：** 如果你按照順序插入 `[10, 20, 30, 40]`，這棵樹會變成這樣：

```
  10
    \
     20
       \
        30
          \
           40
```

它退化成了一條「單向鏈結串列」！原本 $O(\log N)$ 的搜尋速度瞬間崩塌成 $O(N)$。

為了防止這種慘劇，**AVL 樹**誕生了。它在每次插入或刪除節點後，都會進行自我檢查，一旦發現樹長歪了，就會透過「旋轉 (Rotation)」把樹重新喬正。

### 2. AVL 樹的核心規則：平衡因子 (Balance Factor)

AVL 樹規定：**「任何一個節點的『左子樹高度』與『右子樹高度』相差絕對不能超過 1。」**

我們定義一個指標叫做**平衡因子 (Balance Factor, 簡稱 BF)**：

$$\text{BF} = \text{左子樹高度} - \text{右子樹高度}$$

在 AVL 樹中，每個節點的 BF 只允許是 **`-1`、`0` 或 `1`**。 如果某個節點的 BF 變成 `2` 或 `-2`，代表樹「失衡」了，必須立刻發動旋轉。

### 3. 圖解：四種失衡情況與「旋轉魔法」

當樹失衡時，根據「破壞平衡的新節點」長在哪裡，總共分為四種情況：

- **LL 型 (左邊太重)：** 插入在左子節點的左邊 $\rightarrow$ **右旋 (Right Rotation)**
- **RR 型 (右邊太重)：** 插入在右子節點的右邊 $\rightarrow$ **左旋 (Left Rotation)**
- **LR 型 (左子樹的右邊太重)：** 插入在左子節點的右邊 $\rightarrow$ **先左旋、再右旋**
- **RL 型 (右子樹的左邊太重)：** 插入在右子節點的左邊 $\rightarrow$ **先右旋、再左旋**

### 4. 具體例子：一步步建構 AVL 樹

我們來依序插入這五個數字：`[10, 20, 30, 25, 28]`，看看 AVL 樹是如何展現旋轉魔法的。

#### Step 1: 插入 10, 20
都很順利，目前沒有失衡。
```
   10 (BF=-1)
     \
      20 (BF=0)
```

#### Step 2: 插入 30 (觸發 RR 型失衡)
30 接在 20 右邊。
```
   10 (BF=-2)  <-- 失衡！(左高度 0 - 右高度 2 = -2)
     \
      20 (BF=-1)
        \
         30 (BF=0)
```
**診斷：** 30 插入在 10 的**右**小孩(20)的**右**邊，這是 **RR 型失衡**。

**解法：左旋 (Left Rotation)**。 把中間的 20 往上提，變成老大；原本的老大 10 被壓下去變成左小孩。

```
      20 (BF=0)
     /  \
   10    30     <-- 完美平衡！
```

#### Step 3: 插入 25
根據大小規則，25 < 30，所以接在 30 的左邊。
```
      20 (BF=-1)
     /  \
   10    30 (BF=1)
        /
      25 (BF=0)
```

檢查平衡因子：20 的左高 1，右高 2 (相差 1)。30 的左高 1，右高 0 (相差 1)。全都在合法範圍，不需旋轉。

#### Step 4: 插入 28 (觸發複雜的 RL 型失衡)

28 > 25，接在 25 的右邊。
```
      20 (BF=-2)  <-- 注意這裡！(左高 1 - 右高 3 = -2)，20 失衡了！
     /  \
   10    30 (BF=2) <-- 等等，離失衡點最近的其實是 30！(左高 2 - 右高 0 = 2)
        /
      25 (BF=-1)
        \
         28
```

**尋找失衡點：** 我們要找的是「離新插入節點(28)最近」的失衡節點，也就是 **30**。**診斷：** 28 插入在 30 的**左**小孩(25)的**右**邊，這是 **LR 型失衡**。

**解法：LR 型需要「先左旋、再右旋」**
- **動作 A (局部左旋)：** 先對失衡點(30)的左小孩(25)發動左旋。把 28 往上提，25 被壓到左邊。

```
(這只是過渡狀態)
      20
     /  \
   10    30 (BF=2)
        /
      28 (BF=1)
     /
   25
```

這時候我們成功把「LR 型」轉變成了單純的「LL 型」（變成直線了）！

- **動作 B (整體右旋)：** 接著對失衡點(30)發動右旋。把 28 往上提，30 被壓到右邊。

```
(最終完美狀態)
      20 (BF=0)
     /  \
   10    28 (BF=0)
        /  \
      25    30
```

現在所有的節點 BF 都是 0，我們得到了一棵完美平衡的 AVL 樹！

### 5. 平衡樹在實務上的應用

雖然 AVL 樹非常嚴謹，但它的**旋轉成本偏高**（因為規定太嚴格，動不動就要旋轉）。因此在真實世界的工程中，我們通常會使用它的兄弟——**紅黑樹 (Red-Black Tree)**，它稍微放寬了平衡的標準，換取更快的插入與刪除速度。

- **Java, C++ 的標準函式庫：** Java 的 `TreeMap` / `TreeSet`，以及 C++ 的 `std::map` / `std::set`，底層全部都是**紅黑樹**實作的。
    
- **資料庫索引：** MySQL 用的 B-Tree / B+Tree 也是平衡樹概念的延伸（讓每個節點可以存多個數字，將樹變得極度扁平以減少硬碟讀取次數）。
    
- **Python 的現狀：** Python 的標準庫中**沒有**內建 AVL 樹或紅黑樹。實務上如果遇到需要動態維持排序，且要能 $O(\log N)$ 搜尋的場景，會：
    
    1. 使用第三方庫：`from sortedcontainers import SortedList`。
        
    2. 使用內建的二分搜尋模組：`import bisect` 配合一般的 `list`。
