#### 詳細介紹線段樹 (Segment tree)
```
詳細介紹線段樹 (Segment tree)
```

**線段樹 (Segment Tree)** 是資料結構中的「全能瑞士刀」。它將陣列的區間（Segment）以**二元樹**的形式組織起來，利用**分治法 (Divide and Conquer)** 的思想，能夠在 $O(\log N)$ 的極快時間內完成「區間查詢（如總和、最大值、最小值）」與「單點 / 區間修改」。

### 1. 線段樹 vs. 樹狀數組 (BIT) 的差別

你可能會問：我們已經有了 BIT，為什麼還需要線段樹？

- **BIT 的致命傷：** BIT 依賴於「可相減的運算」（例如前綴和：`區間[L, R] = Sum(R) - Sum(L-1)`）。但如果題目要求的是「區間最大值 (Max) 或最小值 (Min)」，BIT 就無能為力了，因為最大值無法相減抵銷。
- **線段樹的強大：** 線段樹**不依賴相減**，它是直接把「符合範圍的積木」拼起來。所以不管是求總和、最大值、最小值，甚至是區間的最大公因數 (GCD)，線段樹都能完美解決！

### 2. 圖解線段樹的儲存結構

我們用一個企業的「營收回報系統」來比喻。 假設有一個長度為 4 的陣列 `A = [3, 5, 2, 10]`，代表 4 家分店的單日營收。我們要求的是**區間總和**。

線段樹會把這 4 家店組成一個層層匯報的二元樹：

- **葉子節點 (Leaf)：** 每家分店（長度為 1 的區間）自己。
- **父節點 (Parent)：** 區域經理，負責把左右兩家分店（子節點）的營收加起來。
- **根節點 (Root)：** 總裁，掌握 `[0~3]` 所有分店的總營收。

**線段樹的形狀：**

```
               總裁 [0~3] 營收: 20
               /                 \
     北區 [0~1] 營收: 8       南區 [2~3] 營收: 12
       /         \              /          \
 店0 [0~0]: 3   店1 [1~1]: 5  店2 [2~2]: 2  店3 [3~3]: 10
```

- **空間特徵：** 線段樹是一棵近乎完全的二元樹，實務上我們不需要用 Node 建立指標，而是直接用一個**一維陣列**來存（通常開 `4 * N` 的大小）。
- **父子關係：** 如果父節點在陣列的索引是 `node`，它的左子節點就是 `2 * node`，右子節點就是 `2 * node + 1`。
    

### 3. 一步步看線段樹的兩大操作

#### 操作一：區間查詢 (Query)

**問題：我要查 `[1, 2]` 區間（店1 和 店2）的總營收。**

我們從總裁（根節點）開始往下問，**原則是：「如果經理的管轄範圍完全在目標區間內，就直接拿他的數字，不再往下問；否則就劈兩半繼續往下問。」**

1. **訪問 `[0~3]` (總裁)：** 目標是 `[1, 2]`。總裁管太寬了，只好把任務拆成兩半，分別問北區 `[0~1]` 和南區 `[2~3]`。
    
2. **訪問 `[0~1]` (北區)：** 任務只要找 `1`。北區管了 `0` 和 `1`，只好再拆半，問 店0 和 店1。
    
    - **問 店0 `[0~0]`：** 不在目標範圍，回傳 0。
        
    - **問 店1 `[1~1]`：** **完全符合！** 直接回傳它的營收 **5**。
        
3. **訪問 `[2~3]` (南區)：** 任務只要找 `2`。拆半問 店2 和 店3。
    
    - **問 店2 `[2~2]`：** **完全符合！** 直接回傳它的營收 **2**。
        
    - **問 店3 `[3~3]`：** 不在目標範圍，回傳 0。
        
4. **匯總：** 店1 加上 店2 = `5 + 2 = 7`。
    

**優勢：** 雖然這個例子很小，但如果是幾萬家店，我們只要拿到「區域經理」的總和就能直接 return，不需要查遍底下的每一家店！時間複雜度 $O(\log N)$。

#### 操作二：單點修改 (Update)

**問題：店1 `[1~1]` 的營收從 5 變成 8（增加了 3）。**

這是一個「由上往下找，再由下往上更新」的過程：

1. **往下找：** 從總裁 `[0~3]` 一路切半走到目標葉子 店1 `[1~1]`。
    
2. **改自己：** 店1 的營收修改為 **8**。
    
3. **往上回報 (Backtrack)：**
    
    - 店1 回報給北區經理 `[0~1]`。北區經理把底下最新的數字重新加總：`3(店0) + 8(店1) = 11`。
        
    - 北區經理回報給總裁 `[0~3]`。總裁把底下最新的數字重新加總：`11(新北區) + 12(南區) = 23`。
        

Plaintext

```
               總裁 [0~3]: 23 (從 20 變 23)
               /                 \
     北區 [0~1]: 11 (變 11)   南區 [2~3]: 12 (不變)
       /         \              /          \
 店0 [0~0]: 3   店1 [1~1]: 8  店2 [2~2]: 2  店3 [3~3]: 10
                 (變 8)
```

**優勢：** 只有在路徑上的主管需要更新數字，旁邊的南區完全不受影響。時間複雜度 $O(\log N)$。

### 4. Python 模板實作 (一維陣列版)

這是 LeetCode 競賽中最標準的寫法。我們使用 `node` 代表當前在樹陣列中的位置，`l` 和 `r` 代表當前節點管轄的區間。
```python
class SegmentTree:
    def __init__(self, data: list):
        self.n = len(data)
        self.data = data
        # 線段樹陣列大小通常開 4 倍的資料長度，確保足夠容納所有節點
        self.tree = [0] * (4 * self.n)
        if self.n > 0:
            self.build(node=1, l=0, r=self.n - 1)

    def build(self, node: int, l: int, r: int):
        """遞迴建立線段樹"""
        if l == r:
            # 走到葉子節點，直接填入原陣列的值
            self.tree[node] = self.data[l]
            return
        
        mid = (l + r) // 2
        left_node = 2 * node
        right_node = 2 * node + 1
        
        # 分治：先蓋好左半邊和右半邊的樹
        self.build(left_node, l, mid)
        self.build(right_node, mid + 1, r)
        
        # 匯總：父節點的值 = 左子樹 + 右子樹
        self.tree[node] = self.tree[left_node] + self.tree[right_node]

    def update(self, node: int, l: int, r: int, idx: int, val: int):
        """單點修改：將 data[idx] 改為 val"""
        if l == r:
            self.tree[node] = val
            return
            
        mid = (l + r) // 2
        left_node = 2 * node
        right_node = 2 * node + 1
        
        # 判斷目標 idx 在左半邊還是右半邊
        if idx <= mid:
            self.update(left_node, l, mid, idx, val)
        else:
            self.update(right_node, mid + 1, r, idx, val)
            
        # 回溯更新父節點
        self.tree[node] = self.tree[left_node] + self.tree[right_node]

    def query(self, node: int, l: int, r: int, ql: int, qr: int) -> int:
        """區間查詢：求 [ql, qr] 範圍內的總和"""
        # 情況 1：當前區間完全在查詢區間之外
        if qr < l or ql > r:
            return 0
            
        # 情況 2：當前區間完全被查詢區間包含
        if ql <= l and r <= qr:
            return self.tree[node]
            
        # 情況 3：部分重疊，劈兩半繼續往下查
        mid = (l + r) // 2
        left_sum = self.query(2 * node, l, mid, ql, qr)
        right_sum = self.query(2 * node + 1, mid + 1, r, ql, qr)
        
        return left_sum + right_sum

# 呼叫範例：
# st = SegmentTree([3, 5, 2, 10])
# 查詢 [1, 2] 總和: st.query(1, 0, st.n-1, 1, 2)
# 更新 index 1 為 8: st.update(1, 0, st.n-1, 1, 8)
```

### 總結心法

如果你的時間有限，想在面試中精通這類問題：

1. **只求和，且只有單點更新** $\rightarrow$ 背下 **BIT** 的超短模板（15行搞定）。
    
2. **求最大值 / 最小值，或是遇到「區間更新」** $\rightarrow$ 毫不猶豫直接召喚 **線段樹 (Segment Tree)**。




#### 四種解法處理最大值 / 最小值: Heap, Monotonic queue, DP, Segment tree
```
動態變化的資料流，隨時要拿最大或最小值 -> Heap (優先佇列)

在平移的固定長度視窗（或動態視窗）中求極值 -> Monotonic Queue (單調隊列)

求所有可能組合中的最大收益/最短路徑，且選擇互相影響 -> DP (動態規劃)
```

這是一個**神級的提問**！你能把這幾個散落在不同章節，但都跟「極值（最大/最小值）」有關的知識點串聯起來比較，代表你的演算法思維已經建立起宏觀的框架了。

的確，這四個工具都在處理「最大值 / 最小值」，但它們應用的場景、查詢的範圍，以及資料變動的方式**完全不同**。

要區分它們，我們只需要問自己三個核心問題：

1. 「查詢的範圍」是全域、固定視窗，還是隨機區間？
2. 「資料的位置（Index）」重要嗎？
3. 我們是在「找」**現有的極值，還是在**「組合/創造」極值？


以下為你詳細拆解這四者的絕對界線與選擇時機：
### 1. Segment Tree (線段樹)

- **核心關鍵字：任意隨機區間 `[L, R]` + 單點/區間更新。**
    
- **資料位置：** 極度重要（必須在陣列中）。
    
- **什麼時候用：** 當題目會**隨機**問你：「第 2 到 5 個元素的最小值是多少？」下一秒又問：「第 10 到 100 個元素的最大值是多少？」 同時，題目還會穿插修改：「把第 4 個元素改成 99」。 因為查詢的區間 `[L, R]` 是**毫無規律、跳躍性**的，只有線段樹能在 $O(\log N)$ 內精準回答任意範圍的最值。
    
- **為什麼不用別的：**
    
    - Heap 不管位置，無法回答「特定區間」的最值。
        
    - 單調隊列只能處理「平移」的區間，無法應付隨機跳躍的 `[L, R]`。
        

### 2. Heap (優先佇列)

- **核心關鍵字：全域 (Global) / Top-K 問題。**
    
- **資料位置：** 完全不重要。數字進了 Heap 就像進了個大黑洞，只要知道誰最大就好，不用管它原本在陣列的哪裡。
    
- **什麼時候用：** 資料不斷地新增、甚至刪除，而你只需要知道「目前全部資料中，最大/最小的那一個是誰？」（或者前 K 個是誰）。 例如：醫院急診室，不斷有病人進來，只要叫出「全場最嚴重的病人」即可，不用管病人是坐在 1 號椅子還是 3 號椅子。
    
- **為什麼不用別的：**
    
    - 如果用線段樹來求全域最大值，簡直是拿大砲打小鳥，不但空間浪費（4 倍陣列），實作也太複雜。
        

### 3. Monotonic Queue (單調隊列)

- **核心關鍵字：滑動視窗 (Sliding Window) / 連續且同向移動的區間。**
    
- **資料位置：** 重要，因為要知道過期了沒，但範圍是**規律移動**的。
    
- **什麼時候用：** 雖然也是求區間最大值，但這個區間 `[L, R]` 是**只能往右滑動，不能回頭，也不能隨機亂跳**（例如：`[0,2] -> [1,3] -> [2,4]`）。
    
- **為什麼不用別的：**
    
    - 既然能用線段樹求任意區間，那能用線段樹解滑動視窗嗎？**可以，但你會被面試官扣分。**
        
    - 線段樹求區間極值要 $O(\log N)$ 時間，而單調隊列透過淘汰機制，均攤時間複雜度是極致的 **$O(1)$**。對於規律滑動的視窗，單調隊列是降維打擊。
        

### 4. Dynamic Programming (動態規劃 DP)

- **核心關鍵字：組合選擇 (Combinations) / 狀態轉移。**
    
- **資料位置：** 代表狀態的進展。
    
- **什麼時候用：** 前面的三個結構，都是資料已經在那邊了，你只是去「找」出來。但 DP 的極值是「做出一系列選擇後，創造出來的最佳結果」**。 例如：「背包問題」求最大價值、「爬樓梯」求最小成本。這些極值不存在於任何單一區間內，而是你每一步決定「拿或不拿」、「走這或走那」，最終**累積出來的最優解。
    
- **為什麼不用別的：**
    
    - 這些極值根本還沒發生，所以你無法把它們存進線段樹或 Heap 裡。
