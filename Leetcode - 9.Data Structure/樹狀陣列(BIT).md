**樹狀數組 (Binary Indexed Tree, 簡稱 BIT)**，又名 Fenwick Tree，是一種極度巧妙的資料結構。它專門用來解決一個痛點：**「如何快速地頻繁修改陣列中的元素，同時又需要快速查詢任意區間的總和？」**

在沒有 BIT 之前，我們面臨兩難：

- **普通陣列：** 單點更新很快 $O(1)$，但算區間和要慢慢加 $O(N)$。
    
- **前綴和陣列：** 算區間和很快 $O(1)$，但如果修改了某個數字，它後面的所有前綴和都要重新計算 $O(N)$。
    

BIT 結合了兩者的優點，讓「單點修改」與「區間查詢」的時間複雜度都降到了極速的 $O(\log N)$。

### 1. BIT 的核心思想：二進位拆分

任何一個十進位的整數，都可以拆成多個「2 的次方」相加。 例如：$7 = 4 + 2 + 1$ （對應二進位 $0111$）。 BIT 就是利用這個特性，把一個長度為 7 的區間，拆成 3 個長度分別為 4、2、1 的小區塊來計算總和，這樣就不用把 7 個數字慢慢相加。

**重要規定：BIT 的陣列索引必須從 `1` 開始（1-based indexing），不能從 `0` 開始！**

### 2. 圖解 BIT 的儲存結構

假設我們有一個原始陣列 `A = [A1, A2, A3, A4, A5, A6, A7, A8]`。 BIT 會創建一個同樣長度的陣列 `C`，而 `C[i]` 儲存的是一段**特定長度**的 `A` 陣列元素總和。

```
原陣列 A:   A1   A2   A3   A4   A5   A6   A7   A8
          ---------------------------------------
C[1]:     [A1]
C[2]:     [----A1+A2----]
C[3]:               [A3]
C[4]:     [-------A1+A2+A3+A4-------]
C[5]:                         [A5]
C[6]:                         [----A5+A6----]
C[7]:                                   [A7]
C[8]:     [-------------A1 到 A8----------------]
```
**看出規律了嗎？**

- **奇數索引** (`C[1], C[3], C[5], C[7]`) 都只管轄 **1 個**元素（自己）。
    
- **偶數索引** 中，`C[2], C[6]` 管轄 **2 個**元素。
    
- `C[4]` 管轄 **4 個**元素。
    
- `C[8]` 管轄 **8 個**元素。
    

每個 `C[i]` 到底管轄幾個元素，完全由 `i` 這個數字在二進位中「最低位的 1（包含後面的 0）」決定。這個神奇的運算稱為 `lowbit`。

### 3. 核心魔法：`lowbit(x)` 函數

`lowbit(x)` 負責找出 `x` 在二進位制中，最低位的 `1` 代表的數值。 在 Python (或 C++) 中，它的實作極度簡潔：
```
def lowbit(x): return x & (-x)
```

_原理：電腦用「二補數」儲存負數（`-x = 反轉 x 的 bit 再加 1`）。當 `x` 和 `-x` 做 `AND(&)` 運算時，除了最低位的 `1` 會保留，其他位數全部都會變成 `0`。_

**舉例：**

- $i = 6$ (二進位 $0110$) $\rightarrow$ 最低位的 1 是 $0010$ (十進位 2) $\rightarrow$ `lowbit(6) = 2`。所以 `C[6]` 管 2 個元素 ($A_5 + A_6$)。
    
- $i = 4$ (二進位 $0100$) $\rightarrow$ 最低位的 1 是 $0100$ (十進位 4) $\rightarrow$ `lowbit(4) = 4`。所以 `C[4]` 管 4 個元素 ($A_1 \sim A_4$)。
    

### 4. 具體操作一步步解說

#### 操作一：查詢前綴和 (Query)

**問題：我要計算前 7 個元素的總和（$A_1 \sim A_7$）**

如果是一般陣列，我們要加 7 次。但在 BIT 中，我們只需要把「拼湊出 7 的積木」加起來。 從索引 `7` 開始，每次減去自己的 `lowbit` 往下跳，直到 0 為止：

1. **出發點：** `i = 7` (二進位 $0111$)。`lowbit(7) = 1`。加上 `C[7]` (代表 $A_7$)。 下一步：$i \leftarrow i - 1 = 6$。
    
2. **跳到：** `i = 6` (二進位 $0110$)。`lowbit(6) = 2`。加上 `C[6]` (代表 $A_5 \sim A_6$)。 下一步：$i \leftarrow i - 2 = 4$。
    
3. **跳到：** `i = 4` (二進位 $0100$)。`lowbit(4) = 4`。加上 `C[4]` (代表 $A_1 \sim A_4$)。 下一步：$i \leftarrow i - 4 = 0$。結束。
    

**結果：** `Sum(7) = C[7] + C[6] + C[4]`。只需 3 次操作！時間複雜度 $O(\log N)$。

#### 操作二：單點更新 (Update)

**問題：我要把 $A_3$ 的值增加 `delta`**

當 $A_3$ 變大了，所有「管轄範圍包含 $A_3$」的 `C[i]` 都要跟著變大。 怎麼知道誰管轄它？從索引 `3` 開始，每次**加上**自己的 `lowbit` 往上爬，沿途更新，直到超過陣列總長度為止：

1. **出發點：** `i = 3` (二進位 $0011$)。`C[3]` 增加 `delta`。`lowbit(3) = 1`。 下一步：$i \leftarrow i + 1 = 4$。
    
2. **爬到：** `i = 4` (二進位 $0100$)。`C[4]` 增加 `delta`。（對照前面的圖，`C[4]` 確實包含 $A_3$） `lowbit(4) = 4`。 下一步：$i \leftarrow i + 4 = 8$。
    
3. **爬到：** `i = 8` (二進位 $1000$)。`C[8]` 增加 `delta`。`lowbit(8) = 8`。 下一步：$i \leftarrow i + 8 = 16$ (假設陣列長度只有 8，結束)。
    

**結果：** 成功更新了 `C[3], C[4], C[8]`。時間複雜度也是極快的 $O(\log N)$。

```python
class BinaryIndexedTree:
    def __init__(self, size: int):
        # BIT 必須 1-based，所以陣列長度開 size + 1
        self.tree = [0] * (size + 1)
        self.size = size

    def lowbit(self, x: int) -> int:
        return x & (-x)

    def update(self, i: int, delta: int):
        """將 A[i] 增加 delta"""
        while i <= self.size:
            self.tree[i] += delta
            i += self.lowbit(i)  # 往上爬，更新所有包含 A[i] 的父節點

    def query(self, i: int) -> int:
        """查詢前綴和 Sum(A[1]...A[i])"""
        total = 0
        while i > 0:
            total += self.tree[i]
            i -= self.lowbit(i)  # 往下跳，收集不同的區塊
        return total

    def query_range(self, left: int, right: int) -> int:
        """查詢任意區間 [left, right] 的總和"""
        return self.query(right) - self.query(left - 1)
```
