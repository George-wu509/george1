
反轉位元 Reverse Bits

LeetCode 190 / LintCode 1333 顛倒給定的 32 位元無號整數（Unsigned Integer）的二進位制位。**提示條件：**

- 請注意，在某些語言（如 Java）中，沒有無號整數類型。在這種情況下，輸入和輸出都將被指定為有號整數類型，並且不應影響您的實作，因為無論整數是有號的還是無號的，其內部的二進位表示形式都是相同的。
- 在 Java 中，編譯器使用二補數（Two's Complement）標記法來表示有號整數。
- **進階思考（Follow up）：** 如果這個函式需要被呼叫很多次，你將如何優化它？

**样例 1：** 输入：
```Python
n = 00000010100101000001111010011100  # 十進位為 43261596
```

输出：
```Python
964176192  # 二進位為 00111001011110000010100101000000
```

解释： 輸入的二進位表示 `00000010100101000001111010011100` 表示無號整數 43261596，將其 32 個位元完全左右顛倒後，得到二進位 `00111001011110000010100101000000`，對應十進位 964176192。

**样例 2：** 输入：
```Python
n = 11111111111111111111111111111101  # 十進位為 4294967293
```

输出：
```Python
3221225471  # 二進位為 10111111111111111111111111111111
```

解释： 輸入的二進位表示無號整數 4294967293，反轉後得到無號整數 3221225471（在 32 位元有號整數環境中則顯示為 -1073741825）。

```Python
class Solution:
    def reverseBits(self, n: int) -> int:
        res = 0
        # 固定迭代 32 次，確保前導零也會被完整推入結果的低位
        for _ in range(32):
            # 1. 將結果左移一位，騰出最右邊的空位
            # 2. 用 (n & 1) 取出 n 目前的最低位，填入 res 的最低位
            res = (res << 1) | (n & 1)
            # 3. 將 n 右移一位，準備處理下一個位元
            n >>= 1
        return res
```


```Python
class Solution:
    def reverseBits(self, n: int) -> int:
        res = 0
        # NeetCode 位置映射寫法：依序取出第 i 位，放到對稱的第 (31 - i) 位
        for i in range(32):
            bit = (n >> i) & 1
            res = res | (bit << (31 - i))
        return res
```

解釋: step1: 題目明確指定是 **32 位元整數**，因此迴圈必須固定執行 **32 次**（不能寫 `while n > 0`，否則 `n` 高位的前導 `0` 會被漏掉，導致反轉後的低位少補零） step2: 透過 `n & 1` 取出 `n` 最右邊的最低位（LSB） step3: 將累積結果 `res` 往左移一位 `res << 1`，並透過位元或運算 `|`（或 `+`）把剛取出的位元放到 `res` 的最低位 step4: 以簡化為 **4 位元** 的 `n = 1101`（十進位 13）為例，`res = 0000`：

- 第 1 輪（`i = 0`）：取出 `n` 最低位 `1` -> `res = 0001`，`n` 右移變成 `0110`
    
- 第 2 輪（`i = 1`）：取出 `n` 最低位 `0` -> `res = 0010`，`n` 右移變成 `0011`
    
- 第 3 輪（`i = 2`）：取出 `n` 最低位 `1` -> `res = 0101`，`n` 右移變成 `0001`
    
- 第 4 輪（`i = 3`）：取出 `n` 最低位 `1` -> `res = 1011`，`n` 右移變成 `0000` step5: 執行滿 32 輪後，原本最低位的位元會被左推 31 次到達最高位（MSB），回傳 `res` 即可
    

n = 0000...0011 (十進位 3) -> res = 1100...0000 (十進位 3221225472)

1. 雖然 n 只有最後兩位是 1，前面 30 位都是 0
    
2. 但因為固定跑 32 次迴圈，這兩個 1 會一路被左推到第 31 與第 30 位
    

解釋: 這道題的本質與 **LeetCode 7（Reverse Integer 整數反轉）** 完全相同，只不過進位制從 **十進位（Base 10）** 變成了 **二進位（Base 2）**： 十進位反轉：`res = res * 10 + (n % 10)`，`n //= 10` 二進位反轉：`res = (res << 1) | (n & 1)`，`n >>= 1`

### **LeetCode 190 / LintCode 1333 - Reverse Bits（反轉位元）**

這道題目是 **Blind 75 & NeetCode 150（Bit Manipulation 分類）** 的核心基礎題，主要考察對 **位元位移（Bit Shifting）**、**位元遮罩（Bit Masking）** 以及 **固定位寬前導零處理** 的掌握度，其進階追問（Follow-up）更常延伸至 **分治位元交換** 與 **查表快取（Lookup Table）** 的系統優化思維。

## **解法解析**

這道題可以透過 **逐位位移模擬** 或 **位元遮罩分治法** 來求解。

### **思路**

1. **為什麼必須固定執行 32 次？**
    
    - 在十進位整數反轉中，`120` 反轉後前導零會被捨棄變成 `21`；但在二進位固定位寬（32-bit）中，`0000...0001`（數值 1）反轉後必須變成 `1000...0000`（數值 $2^{31}$）。
        
    - 如果使用 `while n:` 作為迴圈條件，當 `n` 的高位全為 `0` 時會提早結束迴圈，導致 `res` 沒有左移足夠的次數。因此**必須強制迴圈跑滿 32 次**。
        
2. **兩種等價的位元操作思維**
    
    - **視角一（推入彈出法）**：每次從 `n` 的最右端（第 `0` 位）彈出一位，推入 `res` 的最右端並不斷將 `res` 往左推，經過 32 步後，最先取出的第 `0` 位自然會被推到第 `31` 位。
        
    - **視角二（對稱映射法）**：原數字第 `i` 位的位元 `(n >> i) & 1`，反轉後必定落在 `31 - i` 的位置，直接透過 `res |= (bit << (31 - i))` 精準放置到目標索引上。
        
3. **進階優化（Follow-up：函式被頻繁呼叫時）**
    
    - 若 `reverseBits` 需要被呼叫數百萬次，每次跑 32 輪迴圈仍有優化空間，可採用 **分治位元遮罩（無迴圈 5 步完成）** 或 **位元組查表法（Byte-level Memoization / Lookup Table）** 將 32 位元拆成 4 個 8-bit 的 Byte 查表拼接。
        

## **具體舉例**

為了方便觀察位元移動，假設一個 **4 位元** 整數 `n = 1011`（十進位 `11`），執行過程如下：

|**步驟**|**迴圈開始前 n**|**取出最低位 n & 1**|**res 左移並填入後**|**右移更新後 n**|
|---|---|---|---|---|
|初始化|`1011`|-|`0000`|`1011`|
|第 1 輪|`1011`|`1`|`0001`|`0101`|
|第 2 輪|`0101`|`1`|`0011`|`0010`|
|第 3 輪|`0010`|`0`|`0110`|`0001`|
|第 4 輪|`0001`|`1`|`1101`|`0000`|

4 輪結束後得到 `res = 1101`（十進位 `13`），成功將 `1011` 左右反轉。

## **時間與空間複雜度分析**

- **時間複雜度：O(1)**
    
    - 迴圈固定執行 32 次（對應 32 位元整數的固定位寬），每次內部僅執行常數時間的位元運算（`&`、`|`、`<<`、`>>`），不隨輸入數值大小改變，因此為嚴格的 **O(1)**。
        
- **空間複雜度：O(1)**
    
    - 僅使用 `res` 與迴圈計數器 `i` 等常數個變數，額外空間複雜度為 **O(1)**。
        

## **其他解法**

### **1. 分治法位元遮罩（Divide & Conquer Bit Masking — 無迴圈 O(1)）**

- **思路**：
    
    - 類似歸併排序（Merge Sort）的反轉概念，不使用任何迴圈，直接透過十六進位遮罩分 5 步完成對稱交換：
        
        1. 高 16 位與低 16 位互換
            
        2. 每 16 位中的高 8 位與低 8 位互換（遮罩 `0xff00ff00` / `0x00ff00ff`）
            
        3. 每 8 位中的高 4 位與低 4 位互換（遮罩 `0xf0f0f0f0` / `0x0f0f0f0f`）
            
        4. 每 4 位中的高 2 位與低 2 位互換（遮罩 `0xcccccccc` / `0x33333333`）
            
        5. 每 2 位中的高 1 位與低 1 位互換（遮罩 `0xaaaaaaaa` / `0x55555555`）
            
- **代碼實作**：
    

Python

```
class Solution:
    def reverseBits(self, n: int) -> int:
        n = (n >> 16) | (n << 16)
        n = ((n & 0xff00ff00) >> 8) | ((n & 0x00ff00ff) << 8)
        n = ((n & 0xf0f0f0f0) >> 4) | ((n & 0x0f0f0f0f) << 4)
        n = ((n & 0xcccccccc) >> 2) | ((n & 0x33333333) << 2)
        n = ((n & 0xaaaaaaaa) >> 1) | ((n & 0x55555555) << 1)
        return n & 0xffffffff
```

- **時間複雜度**：O(1)（僅需 5 行位元運算指令）
    
- **空間複雜度**：O(1)
    

### **2. 位元組查表快取法（Byte-by-Byte Lookup Table — 針對 Follow-up 頻繁呼叫）**

- **思路**：
    
    - 32 位元整數可以拆分為 **4 個 8 位元的 Byte**（每個 Byte 只有 $2^8 = 256$ 種可能的值）。
        
    - 預先建立一張長度為 256 的快取表（或使用 `@functools.lru_cache` 記憶化每個 8-bit 數字的反轉結果），每次呼叫時將 32 位元切成 4 段查表後左移組合即可，將 32 步運算縮減為 **4 次查表**。
        
- **時間複雜度**：O(1)（僅 4 次雜湊/陣列查詢）
    
- **空間複雜度**：O(1)（快取表最多僅存 256 個項目）
    

## **總結**

- **面試標準首選解法**：**32 次固定迴圈逐位位移法**，時間 `O(1)`，空間 `O(1)`，程式碼僅 5 行，邏輯直觀且面試官最容易看懂。
    
- **Follow-up 進階亮點**：主動提出 **分治位元遮罩法（5 步無迴圈）** 或 **8-bit 查表快取法（256 大小 Lookup Table）**，能充分展現對底層位元運算與效能優化的深度理解。
    
- **常見易錯點**：忘記補滿 32 次迴圈而誤用 `while n > 0`，導致高位前導零遺失。

### **延伸變形題：LeetCode 191 - Number of 1 Bits（位1的個數）**

編寫一個函式，輸入是一個無號整數（以二進位串的形式），返回其二進位運算式中數字位數為 `'1'` 的個數（也被稱為漢明重量 Hamming Weight）。

Python

```
class Solution:
    def hammingWeight(self, n: int) -> int:
        count = 0
        # Brian Kernighan 演算法：n & (n - 1) 可以精準把 n 二進位中「最右邊的 1」變成 0
        # 有幾個 1 就只會執行幾次迴圈，比固定跑 32 次更快
        while n:
            n &= (n - 1)
            count += 1
        return count
```
