
位元 1 的數量 Number of 1 Bits

LeetCode 191 / LintCode 1332 編寫一個函式，輸入是一個正整數，返回其二進位運算式中設定位（Set Bits，即數字為 `'1'` 的位元）的個數（也被稱為 **漢明重量 Hamming Weight**）。**提示條件：**

- `1 ≤ n ≤ 2^31 - 1`
    
- **進階思考（Follow up）：** 如果這個函式需要被呼叫很多次，你將如何優化它？
    

**样例 1：** 输入：
```Python
n = 11  # 二進位為 00000000000000000000000000001011
```

输出：
```Python
3
```

解释： 輸入的二進位字串 `00000000000000000000000000001011` 中，共有 3 個位元為 `'1'`。

**样例 2：** 输入：
```Python
n = 128  # 二進位為 00000000000000000000000010000000
```

输出：
```Python
1
```

解释： 輸入的二進位字串 `00000000000000000000000010000000` 中，共有 1 個位元為 `'1'`。

**样例 3：** 输入：
```Python
n = 2147483645  # 二進位為 01111111111111111111111111111101
```

输出：
```Python
30
```

解释： 輸入的二進位字串中，共有 30 個位元為 `'1'`（只有最高位與倒數第二位是 `'0'`）。
```Python
class Solution:
    def hammingWeight(self, n: int) -> int:
        res = 0
        # Brian Kernighan 演算法：每次消除 n 二進位中「最右邊的 1」
        while n:
            n &= (n - 1)
            res += 1
        return res
```


```Python
class Solution:
    def hammingWeight(self, n: int) -> int:
        res = 0
        # 逐位檢查最低位是否為 1，並不斷右移直到 n 變為 0
        while n:
            res += n & 1
            n >>= 1
        return res
```

解釋: step1: 觀察 `n & (n - 1)` 的二進位特性：當一個數減 `1` 時，它二進位中最右邊的 `1` 會變成 `0`，而該位置右邊所有的 `0` 都會借位變成 `1` step2: 將 `n` 與 `n - 1` 做位元及運算（`AND`），該最右邊的 `1` 以及其右側所有位元都會被清零，而左側的高位元則完全保持不變 step3: 每執行一次 `n &= (n - 1)`，就代表成功消除了一個 `1`，同時讓計數器 `res += 1`，直到 `n == 0` 為止 step4: 假設 `n = 11`（二進位 `1011`），執行過程如下：

- 第 1 輪：`n = 1011` (11)，`n - 1 = 1010` (10) -> `n & (n - 1) = 1010` (10)，`res = 1`
    
- 第 2 輪：`n = 1010` (10)，`n - 1 = 1001` (9) -> `n & (n - 1) = 1000` (8)，`res = 2`
    
- 第 3 輪：`n = 1000` (8)，`n - 1 = 0111` (7) -> `n & (n - 1) = 0000` (0)，`res = 3` step5: `n` 變為 `0` 結束迴圈，回傳 `3`
    

n = 128 (二進位 10000000) -> res = 1

1. 若用逐位右移法：需要檢查 8 次才能遇到唯一的 1
    
2. 若用 n & (n - 1)：10000000 & 01111111 = 00000000，只需 1 次迴圈就直接結束
    

解釋: 核心技巧為 **Brian Kernighan 演算法**： `n & (n - 1)` 每次精準移除最低位的設定位（Lowest Set Bit）。 因此迴圈次數嚴格等於二進位中 `1` 的個數 $k$，而非總位元長度 32。

### **LeetCode 191 / LintCode 1332 - Number of 1 Bits（位元 1 的數量）**

這道題目是 **Blind 75 & NeetCode 150（Bit Manipulation 分類）** 的必考入門題，同時也是進階動態規劃題 **LeetCode 338（Counting Bits）** 以及 **判斷是否為 2 的冪（LeetCode 231）** 的核心前置基礎。

## **解法解析**

這道題有兩種經典的位元操作思路：**逐位檢查法** 與 **Brian Kernighan 消除最低位 1 法**。

### **思路**

1. **思路一：逐位檢查（Bit Shifting）**
    
    - 利用 `n & 1`（或 `n % 2`）判斷目前 `n` 的最右邊一位（LSB）是否為 `1`。
        
    - 接著將 `n` 無號右移一位 `n >>= 1`（或 `n //= 2`），把下一個位元推到最右邊。
        
    - 重複上述步驟直到 `n == 0` 為止，統計過程中出現 `1` 的次數。
        
2. **思路二：Brian Kernighan 演算法（最推薦面試寫法）**
    
    - 逐位檢查法的缺點是：即使數字只有 1 個 `1`（例如 $2^{30}$），只要這個 `1` 在高位，迴圈還是必須空轉 31 次去跳過前面所有的 `0`。
        
    - 利用 **`n & (n - 1)`** 可以直接跳過中間所有的 `0`，每一次運算都精準消滅最右邊的 `1`：
        
        - 例如 `n = 1100` (12)，`n - 1 = 1011` (11)
            
        - 兩者做 `&` 運算：`1100 & 1011 = 1000` (8)，直接把第 2 位的 `1` 消除了！
            
    - 這個技巧同時也是判斷一個正整數是否為 **2 的次方（Power of Two）** 的一行寫法：`n > 0 and (n & (n - 1)) == 0`。
        
3. **進階優化（Follow-up：函式被頻繁呼叫時）**
    
    - 若函式需要被連續呼叫數百萬次，可以採用 **位元組查表快取（Byte-level Lookup Table）**，預先計算 `0 ~ 255`（8-bit）每個數字包含幾個 `1`，之後每次呼叫只需將 32 位元整數切成 4 個 Byte，做 **4 次陣列查表相加** 即可完成。
        

## **具體舉例**

假設 `n = 21`（二進位為 `10101`），使用 **Brian Kernighan 演算法 `n &= (n - 1)`** 的變數變化如下：

|**步驟**|**迴圈開始前 n（十進位 / 二進位）**|**n - 1（二進位）**|**n & (n - 1)（更新後 n）**|**res（累計 1 的數量）**|
|---|---|---|---|---|
|初始化|`21` (`10101`)|-|`10101`|`0`|
|第 1 輪|`21` (`10101`)|`10100`|`20` (`10100`)|`1`|
|第 2 輪|`20` (`10100`)|`10011`|`16` (`10000`)|`2`|
|第 3 輪|`16` (`10000`)|`01111`|`0` (`00000`)|`3`|

`n` 變為 `0` 結束迴圈，總共只執行了 **3 次** 就回傳結果 `3`（若用逐位右移則需執行 5 次）。

## **時間與空間複雜度分析**

- **時間複雜度：O(k) ≈ O(1)**
    
    - 其中 `k` 為輸入整數 `n` 的二進位中 `1` 的個數。對於 32 位元整數而言，$k \le 32$，最壞情況（如 `n = 2^32 - 1`）執行 32 次，平均情況執行 16 次，因此為嚴格常數時間 **O(1)**。
        
- **空間複雜度：O(1)**
    
    - 僅使用 `res` 單一計數器變數，額外空間複雜度為 **O(1)**。
        

## **其他解法**

### **1. 內建函式一行解（Built-in Function）**

- **思路**：
    
    - Python 3.10+ 提供了原生的 `n.bit_count()` 方法（底層以 C 語言 POPCNT 硬體指令或查表實作）；舊版 Python 則可用 `bin(n).count('1')`。
        
- **注意**：
    
    - 刷題測試或日常開發非常推薦使用，但**技術面試時面試官通常希望看到手寫位元運算**，切勿只寫內建函式交差。
        
- **時間複雜度**：O(1)
    
- **空間複雜度**：O(1)（`bin(n)` 會產生長度最多 34 的字串，仍屬常數空間）
    

### **2. 位元組查表法（Lookup Table — 針對 Follow-up 頻繁呼叫）**

- **思路**：
    
    - 預先建立一張長度為 `256`（$2^8$）的陣列 `table`，記錄 `0 ~ 255` 每個 8 位元整數中 `1` 的個數。
        
    - 每次呼叫 `hammingWeight(n)` 時，透過遮罩 `0xff` 每次取出 8 位元查表並右移 8 位，只需 4 次查表即可得到答案：
        

Python

```
class Solution:
    def __init__(self):
        # 預先計算 0 ~ 255 的漢明重量表
        self.table = [0] * 256
        for i in range(1, 256):
            self.table[i] = self.table[i >> 1] + (i & 1)

    def hammingWeight(self, n: int) -> int:
        return (
            self.table[n & 0xff] +
            self.table[(n >> 8) & 0xff] +
            self.table[(n >> 16) & 0xff] +
            self.table[(n >> 24) & 0xff]
        )
```

- **時間複雜度**：O(1)（固定 4 次陣列索引查詢，無迴圈）
    
- **空間複雜度**：O(1)（僅需 256 個整數的靜態查表空間）
    

## **總結**

- **面試最推薦解法**：**Brian Kernighan 演算法 `n &= (n - 1)`**，時間 `O(1)`（實際僅執行 `1` 的個數次），空間 `O(1)`，程式碼簡潔且能順帶展示對二進位進位性質的理解。
    
- **Follow-up 進階亮點**：當函式被高頻呼叫時，主動提出 **8-bit Lookup Table（256 大小查表法）**，將運算降為固定 4 次查表。
    
- **核心記憶口訣**：`n & (n - 1)` = **消除最右邊的 1**；`n & (-n)` = **保留最右邊的 1**（常用於樹狀陣列 Fenwick Tree 的 `lowbit`）。

### **延伸變形題：LeetCode 338 - Counting Bits（位元計數）**

給你一個整數 `n` ，對於 `0 <= i <= n` 中的每個 `i` ，計算其二進位表示中 `1` 的個數 ，返回一個長度為 `n + 1` 的陣列 `ans` 作為答案（要求時間複雜度為 $O(n)$，不能對每個數字單獨跑 $O(\log n)$ 迴圈）。

Python

```
class Solution:
    def countBits(self, n: int) -> list[int]:
        dp = [0] * (n + 1)
        # 直接套用本題的 Brian Kernighan 性質：
        # i 比 i & (i - 1) 剛好多了「最右邊的那一個 1」，且 i & (i - 1) 必然小於 i（已經計算過）
        for i in range(1, n + 1):
            dp[i] = dp[i & (i - 1)] + 1
        return dp
```
